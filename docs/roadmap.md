## 순서 — 무엇이 무엇을 막는가

화살표는 **"이게 저걸 막는다"** 다. 왼쪽이 끝나야 오른쪽을 할 수 있다.

```
Phase 1   #18 재접속 스파이크 ─┬─→ ⑦ 재시작 전략 ─┐
                               │                    ├─→ ⑨ 재접속 복원
          #19 핸드오프 스파이크 ┘   ② 데몬의 언어 ─┘
                                        │
                                        │  (언어·구조가 정해져야)
                                        ▼
Phase 2   #20 shim 스파이크 ─→ ⑧ codex 경로 ─→ ⑥ 신호등 색 ─┐
                                                              ├─→ #22 데몬
                                                              ┘
                                        │
                                        ▼
Phase 3   ① 웹 스택 ─┬─→ #25 레일 둘 ────────────────┐
                      │                                │
          ③ 좌표 ─────┼─→ #23 캔버스 ─→ ⑩ 밀 자리 없을 때
                      │        └────────→ #24 확대 보기
          ⑥ (Phase 2) ─→ #26 신호등
          #28 안 그린 화면 넷 (다른 것을 안 막는다)
                                        │
                                        ▼
Phase 4   ④ 앱은 언제 ─→ #27 Tauri        #21 다른 기계에서 재기
```

**두 갈래가 먼저다.** ② 와 ⑦ 은 서로를 좁힌다 — ⑦ 에서 핸드오프를 고르면 Bun 이 탈락하고,
② 에서 Bun 을 고르면 ⑦ 이 (b) 로 정해진다. **그래서 이 둘을 같이 본다.**

**#18 이 ⑦ 을 바꿀 수 있다.** SIGWINCH 흔들기만으로 화면이 되살아나면 링버퍼를 넘길 이유가 줄고
핸드오프의 값이 떨어진다. **그래서 스파이크가 결정보다 먼저다.** 이게 이 프로젝트의 규칙이다 —
잴 수 있는 것을 재기 전에 정하지 않는다.

**#25 를 #23 보다 먼저 둔다.** 캔버스는 경쟁자들이 다 갖고 있고, 우리가 다르게 하는 것은
**기다리는 것이 맨 위로 오는 목록**이다. 늦어져서 뭔가를 못 만들게 되면 캔버스가 아니라 목록이 남아야 한다.

**#21 은 아무것도 안 막는다.** 언제든 할 수 있고, 새 기계가 생기면 그때 한다.
