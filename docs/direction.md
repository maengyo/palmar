# 방향 — 2026-11-02, 에이전트 쓰는 방식이 바뀐 자리에서 palmar 는 어디로 가나

읽는 사람이 하나인 작업 문서다. **조사**는 조사라고 적었고, 우리가 잰 것은 잰 것이라고 적었다.
결정은 사람이 한다 — 여기 적힌 것은 후보와 근거다.

## 1. 2026년 가을, 에이전트는 어떻게 쓰이나 (조사)

- **데스크톱 앱이 왔다.** Anthropic 이 2026-04 에 Claude Code 데스크톱을 **병렬 세션** 중심으로
  다시 만들었다: 세션 사이드바(상태·프로젝트별 필터, PR 이 닫히면 자동 보관), 세션마다 자동
  worktree, 끌어서 배치하는 레이아웃, 내장 터미널·파일 편집기. OpenAI Codex 앱(macOS·Windows)은
  여러 터미널 탭, PR 리뷰, SSH 원격, 스케줄된 작업, 앱 안 브라우저까지 넣었다. 둘 다 "터미널에서도,
  IDE 에서도, 앱에서도, 클라우드에서도" 를 내건다.
- **병렬 실행기 한 묶음이 생겼다.** Conductor(맥, worktree 하나에 에이전트 하나, PR·리뷰 흐름),
  Vibe Kanban(카드=worktree=에이전트, 회사는 닫았고 프로젝트는 남음), Nimbalyst(Crystal 후신),
  Claude Squad(tmux 위 TUI), **Agent Deck**(백그라운드 데몬 + TUI/데스크톱 클라이언트, 에이전트
  카드와 라이브 pane, 상태를 "작업 중·생각 중·대기" 로 셈, 오케스트레이터가 워커에게 위임,
  cron·GitHub 이슈로 디스패치). 공통 모양은 **"데몬이 에이전트를 들고, 클라이언트는 붙었다 뗀다"**
  와 **"worktree 하나에 에이전트 하나"** 다.
- **사람들이 아쉬워하는 것** (Claude Code 데스크톱 이슈, 조사): 세션 둘을 **나란히** 보기,
  `⌘1·⌘2` 로 세션 바로 가기, 터미널 손버릇이 더 빠르다는 말("Warp + CLI 가 아직 빠르다").
  Codex 쪽은 "탭 30개는 인지 부담" 이라는 말과 에이전트 간 자동 핸드오프 요구.
- **터미널은 안 죽었다.** 같은 조사에서 CLI 에이전트 목록은 더 길어졌다(Claude Code, Codex,
  OpenCode 212k 스타, Cursor CLI, Antigravity CLI). 데스크톱 앱들은 그 CLI 를 **안에 품는** 쪽이다.

## 2. palmar 와 겹치는 것, 안 겹치는 것

| | 데스크톱 앱(Claude Code·Codex) | 병렬 실행기(Conductor·Agent Deck) | palmar |
|---|---|---|---|
| 에이전트 | 자기 것 하나 | 여럿, 대부분 Claude 중심 | **무엇이든 — 도구 목록이 없다**(원칙 4) |
| 세션 보기 | 사이드바 목록, 하나씩 | 카드 + 포커스된 pane 하나 | **캔버스에 여럿을 같이**, 자리·크기는 내가 |
| 상태 | 자기 훅 | 자기 통합 | 훅 · 제목 · 출력, 셋을 겹쳐 읽음 |
| 살아남기 | 앱이 살아 있는 동안 | 데몬 | 데몬 |
| worktree | 자동 | 자동, 핵심 기능 | **없음** |
| 오케스트레이션·디스패치 | 일부 | 핵심 | **없음** |
| 설치 | 설치 프로그램 | brew·바이너리 | 파이썬 한 줄 |

palmar 가 **혼자 가진 것**은 둘이다. (1) 터미널 여럿을 **한 화면에 나란히**, 자리를 기억한 채로 —
위 조사에서 데스크톱 앱 사용자가 가장 먼저 아쉬워하는 그것. (2) **에이전트를 안 가린다** — 셸을
열 뿐이라 내일 나올 CLI 도 그냥 된다.

palmar 가 **없는 것** 중 다른 모두가 가진 것은 **worktree** 다. 병렬로 돌리는 사람은 거의 다
worktree 로 돌리고, 지금 palmar 에서는 그걸 손으로 한다(`git worktree add` 를 터미널에서).

## 3. 그래서 — 후보 넷 (결정은 사람이)

**A. 캔버스를 더 캔버스답게.** 나란히 보기가 palmar 의 것이면 그걸 끝까지: 세션 바로 가기
(`Ctrl/⌘ 1…9`), 두 창을 반반으로 맞추는 한 동작, 캔버스마다 한 프로젝트. 작고 원칙과 안 부딪힌다.

**B. worktree 한 동작.** "이 폴더의 새 worktree 에서 터미널 열기" — 폴더 레일의 `+` 옆에 하나.
`git worktree add` 한 줄을 대신 쳐 주는 것이고, 브랜치 이름만 묻는다. 이것은 **"파일을 만들거나
지우지 마라"** 원칙의 가장자리다(폴더 만들기까지가 런처의 일이라고 돼 있다; worktree 는 폴더
만들기이기도 하고 git 명령이기도 하다). 넣는다면 그 줄을 다시 적어야 한다.

**C. 데스크톱 앱을 앞에.** `app/` 창은 이미 있다(맥 메뉴 바까지). 지금은 "브라우저가 기본, 창은
있으면" 인데, 조사가 말하는 흐름은 반대다. ④(앱을 언제 내는가)를 당긴다는 뜻이고, 세 OS 빌드를
내는 비용이 붙는다(#12). 기능이 아니라 **배포**의 결정이다.

**D. 오케스트레이션은 안 한다.** 위임·디스패치·핸드오프는 Agent Deck 과 Conductor 가 이미 하고,
palmar 가 거기 들어가면 "에이전트를 모른다" 는 성질을 버려야 한다. 이건 하지 말자는 후보다 —
**안 넣을 것을 정하는 것도 결정이다**(원칙 6).

내 추천은 **A 와 D 는 지금, B 는 원칙 줄을 고칠지 보고, C 는 ④ 와 함께** 다. 근거: 조사에서
사람들이 데스크톱 앱에 아쉬워하는 첫 번째가 정확히 palmar 가 이미 하는 것(나란히 보기)이고,
그걸 더 잘하는 쪽이 남의 핵심 기능(worktree·오케스트레이션)을 뒤쫓는 쪽보다 싸다.

## 4. 바로 할 수 있는 작은 것 (A 의 조각)

- `Ctrl/⌘ 1…9` — 목록 순서대로 터미널 바로 가기. 단축키 판에 적는다.
- 받은편지함의 줄을 눌렀을 때 그 터미널이 **다른 캔버스**에 있으면 캔버스까지 넘어간다(지금 됨 —
  적어 둠).
- 캔버스 이름을 폴더 이름으로 제안(새 캔버스를 폴더에서 열 때).
