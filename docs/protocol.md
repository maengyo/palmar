# 프로토콜 — 데몬 ↔ 브라우저

이 문서가 계약이다. 데몬(`palmar/daemon.py`)과 브라우저(`web/`)는 이것만 보고 만든다.
② 가 "Bun 으로 옮길 수 있게" 를 조건으로 파이썬을 골랐으므로, **여기 적힌 것만 지키면 데몬을 갈아 끼울 수 있어야 한다.**
바꾸려면 이 문서를 먼저 고친다. 스파이크 D·E·F·G·I 에서 실측된 값이 기준이다.

**2026-09-08 에 붙은 것:** 캔버스(⑪)와 이름(⑫). 세션에 `canvas`·`name` 이 생기고, `/api/canvases` 넷과
`PATCH /api/sessions/<id>` 가 생기고, `/events` 에 `canvas`·`canvases`·`canvas_gone` 이 생겼다.
**미니맵과 목록 접기는 여기 없다** — 브라우저만의 것이다(아래 "없는 것").

## 뜨기

```
python3 -m palmar            # 127.0.0.1:8801. --port 만 받는다. host 옵션은 없다.
```

뜨면서 하는 일 (순서대로, 하나라도 실패하면 뜨지 않는다):
1. `~/.palmar/` `~/.palmar/bin/` `~/.palmar/run/` 을 0700 으로 만든다. **이미 있는데 소유자가 다르거나
   group/other 쓰기 비트가 있거나 심볼릭 링크면 거부한다** (#29). 0755 처럼 읽기만 열린 것은 거부하지
   않고 0700 으로 조인다. **`~/.palmar/run/lock` 에 배타적 `flock` 을 잡는다 — 못 잡으면 이미 다른
   palmard 가 이 HOME 을 쓰는 것이라 그 URL 을 찍고 뜨지 않는다(데몬은 HOME 당 하나, #2). 락을 잡은
   데몬만 아래 토큰 회전과 고아 `.json` 삭제를 한다** — 안 그러면 둘째 데몬이 첫째의 pane 설정을 지워
   훅이 소리 없이 빠진다. `run/` 의 고아 `<id>.json` 을 지운다(지난 데몬의 pane 은 이제 없다, ⑦=b).
2. 토큰을 만든다 — `secrets.token_urlsafe(32)`. `~/.palmar/run/token` 에 0600 으로 쓴다.
   **다시 뜨면 토큰도 새로 난다** — 열려 있던 페이지의 토큰은 그 순간부터 틀린 토큰이다(아래 "인증").
3. shim 을 `~/.palmar/bin/claude` 에 쓴다 (아래 "shim").
4. `web/` 을 정적으로 낸다. `index.html` 을 낼 때 **첫** `</head>` 앞에
   `<script>window.PALMAR_TOKEN="…"</script>` 를 심는다. **토큰은 이 길로만 브라우저에 간다.**
   그래서 `index.html` 에 그 닫는 태그는 정확히 하나여야 한다 — 주석에도 그 글자를 적지 않는다
   (실제로 한 번 주석 안에 심겨 토큰이 안 실렸다).
5. 마지막 줄에 `http://127.0.0.1:8801` 을 찍는다.

## 인증 — 모든 요청에

- **`Origin` 헤더가 있으면** `http://127.0.0.1:<port>` 또는 `http://localhost:<port>` 여야 한다. 아니면 `403`.
  (없으면 통과 — 같은 출처 fetch·curl 은 Origin 을 안 보낸다.)
- **`Host` 헤더가 있으면** `127.0.0.1:<port>` 또는 `localhost:<port>` 여야 한다. 아니면 `403`.
  DNS 리바인딩(공격자 도메인 → 127.0.0.1)으로 `index.html` 의 토큰을 읽어 가는 길을 막는다(#29).
  (2026-09-07 데몬 구현에서 추가. 브라우저는 자기 주소로 접속하니 영향이 없다.)
- **모든 HTTP 응답에 `X-Frame-Options: DENY` 와 `Content-Security-Policy: frame-ancestors 'none'` 를 붙인다.**
  남의 페이지가 palmar UI 를 iframe 으로 감싸 클릭재킹(한 번 눌러 터미널에 포커스 → 키 입력을 남의 셸로)을
  못 하게 막는다(#10, 2026-09-08 추가).
- **웹소켓 업그레이드와 상태를 바꾸는 요청(POST·PATCH·DELETE)은 `?token=` 이 맞아야 한다.** `hmac.compare_digest`. 아니면 `403`.
  **캔버스 만들기·이름 바꾸기·순서 바꾸기·지우기와 세션 이름 바꾸기·캔버스 옮기기도 여기에 든다**
  (2026-09-08 에 `PATCH` 가 들어오면서 이 줄에 붙었다). Origin·Host 검사도 똑같이 받는다.
  **새 경로에 예외를 두지 않는다.**
  **예외는 하나뿐: `/hook/claude`** — 토큰이 틀려도 `200 {}` 를 돌려주고 **무시한다**. 훅은 0 으로 끝나야 하기 때문이다.
  Origin·Host 가 틀린 것만 `403` (훅은 둘 다 안 보낸다).
- **데몬 자리에 서는 것은 이 셋을 다 지킨다.** `dev/dev-stub.py` 도 데몬 자리에 서고 `index.html` 에 같은
  토큰을 심으므로 예외가 아니다. (2026-09-08 실측: 스텁에 `Host` 검사와 두 헤더가 빠져 있어
  `curl -H 'Host: evil.example' http://127.0.0.1:<port>/` 가 `200` 에 몸 안의 `PALMAR_TOKEN` 까지 돌려줬다.
  제품 데몬은 같은 요청에 `403` 이었다. 스텁을 제품에 맞췄다.)
- 정적 파일 `GET` 은 토큰 없이 된다 (토큰이 거기 실려 나가니까).
- 정적 파일 경로는 `Path.is_relative_to(WEB)` 로 가른다. `startswith` 금지.
- **토큰이 바뀌었을 때(데몬 재시작):** 브라우저는 `/events` 가 **열리지도 못하고** 닫히면 `GET /` 을 다시 받아
  심긴 토큰이 자기 것과 다를 때만 새로 고친다. 같으면(데몬이 아직 안 떴다) 백오프 재시도만 이어진다.
  (2026-09-07 통합 실측: 이 처리가 없을 때 페이지는 영원히 "reconnecting…" 이었다.)

**뿌리(roots):** 사용자 홈(`$HOME`, 언제나) + `/Users/*` `/home/*` 중 **지금 uid 가 소유한**
읽기·실행 가능한 것. `cwd` 와 `path` 는 `resolve()` 뒤에 뿌리 중 하나 아래여야 한다.
심볼릭 링크도 `resolve()` 뒤 기준이고, **소유자도 푼 경로에서 잰다**.

**남의 홈은 뿌리가 아니다 (#31, 2026-09-08).** 전에는 `os.access(R_OK|X_OK)` 만 봤다 —
리눅스 홈은 보통 `drwxr-xr-x` 라 전부 통과했고, WSL 에서 `aa` 로 돌리는데 `/home/bb` 가
디렉터리 레일에 떠서 거기 셸을 열 수 있었다. 셸은 그대로 `aa` 로 도니 권한 상승은 아니지만,
**뿌리는 곧 `cwd` 검사의 바닥이라** 넓은 만큼 `POST /api/sessions` 가 받아 준다.
홈이 여럿인 사람은 자기 것을 다 본다. 실측(macOS, uid 501): 전 `["/Users/me", "/Users/Shared"]`
→ 후 `["/Users/me"]`. **`/Users/Shared` 가 이 규칙에 걸려 빠진다** — root 소유(`drwxrwxrwt`)다.

**표에 없는 메서드는 `405`.** `GET`·`HEAD` 만 정적 파일로 간다. 없는 `/api/…` `/hook/…` 은 `405` 가 아니라 `404`.
`Content-Length` 가 1MB 를 넘으면 `413`, 몸을 다 안 보내면 `408` (전부터 그랬다 — 새 경로도 같다).
4xx 의 몸은 `{"error": "사람이 읽는 한 줄"}` 이다(`204` 는 몸이 없다). 브라우저는 그 문자열을 토스트에
그대로 쓴다 — 그러니 경로나 내부 사정을 담지 마라.

```jsonc
// Session
{ "id": "k3Jx…",            // secrets.token_urlsafe(16) 이 내는 22자 URL-safe 토큰. 순번 금지 (#29)
  "cwd": "/Users/me/work/api",
  "cols": 120, "rows": 33,
  "status": "unknown",       // 아래 "상태"
  "title": null,             // 에이전트가 마지막으로 세운 창 제목. 상태를 여기서 읽는다 (#38)
  "agent": null,             // "claude" | "codex" | "opencode" | null — 훅이 알려 준 것만
  "alt": false,              // 지금 alt-screen 안인가
  "created": 1788780000.0,   // epoch 초
  "last_event": null,        // 마지막 훅 이벤트명, 없으면 null
  "canvas": "Qm2p…",         // 붙어 있는 캔버스의 id. **null 이 아니다** — 세션은 늘 어딘가에 있다 (⑪)
  "name": null }             // 사람이 준 이름. null 이면 브라우저가 경로로 이름표를 만든다 (⑫)

// Canvas
{ "id": "Qm2p…",             // Session id 와 같은 모양의 URL-safe 토큰. 순번 금지
  "name": null,              // 사람이 준 이름. null 이면 브라우저가 seq 로 이름표를 만든다 (⑫)
  "order": 0,                // 탭 순서. 0부터 빈틈없이, 작은 것이 왼쪽. **끌면 바뀐다**
  "seq": 1 }                 // 몇 번째로 만들어졌나. 1부터, 되쓰지 않는다. **자리가 바뀌어도 안 바뀐다**

// Dirs
{ "path": "/Users/me/work",
  "entries": [ { "name": "api", "git_branch": "main", "has_children": true },
               { "name": "docs", "git_branch": null, "has_children": false } ] }

// Dirs — 뿌리 목록 (path 없이 GET /api/dirs). path 는 null 이고 name 은 절대 경로다.
// entries[0] 이 사용자 홈이다 — 브라우저는 그것으로 "~" 를 만든다. 나머지는 이름순.
{ "path": null,
  "entries": [ { "name": "/Users/me",     "git_branch": null, "has_children": true },
               { "name": "/Users/Shared", "git_branch": null, "has_children": false } ] }
```

`entries` 는 **폴더만**, 점으로 시작하는 것은 뺀다, 이름순(`casefold`). `git_branch` 는 `<dir>/.git/HEAD` 한 줄만
읽어 얻는다 — `git status` 는 절대 돌리지 않는다(cate 가 45% CPU 를 낸 자리). `.git` 이 파일이면(worktree)
그 안의 `gitdir:` 을 따라간다. 분리 HEAD 면 짧은 해시 7자(`null` 이면 "저장소 아님" 으로 보이니까). 못 읽으면 `null`.

## 캔버스 (⑪ ⑫, 2026-09-08)

세션 하나는 **반드시 캔버스 하나**에 속한다. 탭은 캔버스 **위**에 붙는다(원노트·윈도우 탐색기 식).
탭은 **전환기**이고, 안 놓치는 일은 왼쪽 목록이 맡는다 — 그래서 탭에는 점 하나 말고 아무것도 안 붙는다(⑪).

- **데몬이 뜨면 캔버스가 하나 있다.** `name` 은 `null`, `order` 는 `0`. 이름표는 브라우저가 만든다.
  캔버스가 없는 순간은 없다 — 그래서 `POST /api/sessions` 는 캔버스가 없어서 실패하지 않는다.
- **id 는 세션 id 와 같은 모양**(`secrets.token_urlsafe(16)`, 22자)이다. 캔버스 id 에는 권한이 걸려
  있지 않으니(pane id 와 달리 훅 URL 도 `/pty` 도 열지 않는다) #29 가 추측 불가를 요구하는 자리는
  아니다 — **id 모양을 하나로 두려고** 같게 한다. 순번은 어느 쪽에도 안 쓴다.
- **이름 규칙(캔버스·세션 공통).** 문자열이면 앞뒤 공백을 떼고 **1–64 글자**, 제어문자
  (`\x00`–`\x1f`, `\x7f`) 금지. 어기면 `400`. `null`·빈 문자열·공백뿐인 문자열은 **이름 없음**으로
  같게 다루고 `null` 로 저장한다(= 이름 지우기는 `{"name": null}` 이나 `{"name": ""}` 둘 다 된다).
  **64 는 잰 값이 아니라 골라 잡은 값이다** — 데몬이 오래 도니(⑦=b) 길이 없는 문자열을 받아
  두지 않으려는 것뿐이고, 한 곳에 있어 바꾸기 싸다.
- **이름은 유일하지 않다.** 같은 이름의 캔버스가 둘 있어도 된다 — 가리키는 것은 언제나 id 다.
  유일성을 강제하면 이름 바꿀 때마다 실패가 생기는데 그만한 값이 없다.
- **이름은 셸에 안 닿는다.** pane 환경은 지금 그대로다(`PALMAR_PANE`·`PATH`·`TERM`…). 이름은 화면에
  찍히는 데이터일 뿐이라 명령줄에도 rc 에도 환경변수에도 들어가지 않는다. **클라이언트가 명령을
  고를 길은 여전히 없다.** 브라우저는 이름을 `textContent` 로만 넣는다 — `innerHTML` 금지.
- **왼쪽 목록은 캔버스로 거르지 않는다.** 다른 캔버스의 세션에 붙는 캔버스 이름표는
  `session.canvas` 와 캔버스 목록으로 브라우저가 만든다 — 그 배지를 위한 필드는 따로 없다.

**순서는 데몬이 갖는다.** `order` 는 0부터 빈틈없는 정수, 작은 것이 왼쪽. 브라우저마다 다르지 않다 —
왼쪽 목록과 같은 이유로 두 브라우저가 같은 탭 줄을 봐야 한다.
탭을 끌어 놓으면 브라우저는 **지금 있는 캔버스 전부를 새 순서로** `POST /api/canvases/order` 한다.
하나씩 `PATCH` 하지 않는 이유: 순서는 집합의 성질이라 중간 상태가 남으면 두 브라우저가 서로 다른
탭 줄을 그린다. 한 번에 바꾸면 방송도 한 프레임이다.
보낸 목록이 지금 집합의 재배열이 정확히 아니면 `409` 다 — 그 사이에 누가 캔버스를 만들었거나 지운
것이고, 그 브라우저는 이미 그 이벤트를 받았으니 다시 보내면 된다.

**지우기는 빈 캔버스만 된다 — PROVISIONAL.** 세션이 하나라도 있으면 `409`, 마지막 하나여도 `409`.

- **자동으로 옮기지 않는 이유:** 창들이 사용자가 안 보고 있는 캔버스에 나타난다. 좌표는 session `id`
  로 저장돼 있어(아래 "위치·크기·이름·캔버스 소속") 옮겨진 창이 거기 있던 창 **위에** 앉고, 그러면
  밀어내기가 돌아 남의 캔버스 배치가 흐트러진다. 옮기는 길은 이미 있으니
  (`PATCH /api/sessions/<id>` 의 `canvas`) **사용자가 먼저 옮기게 한다.**
- **지우면서 셸을 죽이는 길은 논외다.** 원칙 2("세션은 UI 보다 오래 산다")를 정면으로 어긴다.
  탭 하나 닫는 몸짓으로 도는 에이전트가 사라지면 안 된다.
- **마지막 하나를 남기는 이유:** 캔버스가 0개면 새 세션이 갈 데가 없다.
- **캔버스는 스스로 없어지지 않는다.** 마지막 세션이 `DELETE /api/sessions/<id>` 나 셸 종료로 사라져도
  그 캔버스는 그대로 남는다 — `gone` 하나만 가고 `canvas_gone` 은 **안 간다**. 캔버스를 없애는 길은
  `DELETE /api/canvases/<id>` 하나뿐이고, 그래서 방금 비운 캔버스는 그 자리에 그대로 있다가
  다음 세션을 받는다. (2026-09-08 실측으로 확인하고 이 줄을 적었다 — 코드가 맞고 문서가 말을 안 했다.
  자동으로 없애면 세션 하나 닫는 몸짓이 남의 탭 줄까지 다시 매기고, 보고 있던 탭이 발밑에서 사라진다.)
- **PROVISIONAL:** "빈 것만 지운다" 와 "지우면서 옆 캔버스로 옮긴다" 중 어느 쪽인지는 제품 결정이다
  (⑪ "같이 정할 것"). 파괴적이지 않은 쪽을 골라 뒀을 뿐이고, 사람이 정하면 이 문단과 `409` 두 줄만 바뀐다.

**새 세션이 어느 캔버스에 뜨는지는 브라우저가 정한다.** 데몬에는 "지금 보고 있는 캔버스" 가 없다 —
브라우저 둘이 서로 다른 탭을 보고 있을 수 있기 때문이다. 그래서 `POST /api/sessions` 가 `canvas` 를
실어 보낸다. ⑪ 의 열린 질문("지금 캔버스인가 그 폴더의 캔버스인가")은 **이 한 칸을 무엇으로 채우느냐**
이지 프로토콜이 아니다 — 여기서 정하지 않는다.

**경로 맞추는 순서.** `/api/canvases/order` 를 `/api/canvases/<id>` 보다 **먼저** 맞춘다.
id 는 22자라 `order` 와 부딪힐 수 없지만, 갈아 끼울 구현이 다르게 짜지 않도록 여기 적어 둔다.

**이름 없는 캔버스의 이름표는 `seq` 로 만든다** — `"canvas <seq>"`. `order` 로 만들면 탭을 끌어
자리를 바꾸는 순간 이름표가 서로 바뀌어, 사용자에게는 캔버스 이름이 저절로 바뀐 것으로 보인다
(보고 2026-09-08). 지우고 새로 만들면 번호가 건너뛴다 — 번호는 자리표이지 순번이 아니다.

**탭의 점은 저장하지 않는다 — 계산한다.** 그 캔버스에 속한 세션 중 `status == "waiting"` 인 것이
하나라도 있으면 켠다. 그게 전부다(⑪: "그 이상 안 넣는다") — 개수도 아니고 `done`·`working` 도 아니다.
브라우저는 캔버스로 거르지 않은 세션 전부를 이미 들고 있으므로(`hello`·`session`·`gone`) 한 번 훑으면
나온다. **그래서 점을 위한 메시지도 필드도 없다.**
`waiting` 은 쳐다본다고 안 꺼지므로(아래 "상태") **탭을 눌러도 점은 안 꺼진다** — 다음 훅이 꺼 준다.
색은 ⑥ 이 미정이라 `status` 의 CSS 변수를 그대로 쓴다. 점을 위한 새 색을 만들지 않는다.

## 상태 (`status`)

근거는 둘이다. **훅이 말해 주면 훅을 쓰고, 훅이 없으면 창 제목을 본다.** 화면(글자)을 읽어 정하지는
여전히 않는다 — 제목은 에이전트가 스스로 내보내는 것이라 화면 파싱이 아니다.

| 훅 `hook_event_name` | → `status` | `agent` |
|---|---|---|
| `SessionStart` | `idle` | 그 에이전트 |
| `UserPromptSubmit` | `working` | 그 에이전트 |
| `PermissionRequest` | `waiting` | 그 에이전트 |
| `Notification` | (바꾸지 않음) | 그 에이전트 |
| `Stop` | `done` | 그 에이전트 |
| `SessionEnd` | `unknown` | `null` |
| (훅이 온 적 없음) | 아래 "제목으로 읽기" | `null` |

`/hook/claude` 로 온 훅은 **어느 이벤트든** `agent` 를 `"claude"` 로 적는다 — `SessionStart` 의 http 훅이 안 온
관측이 있어(스파이크 E, 1회) 그것에만 기대지 않는다. 올리는 쪽은 약한 근거로도 된다. `last_event` 는 모르는
이벤트명이라도 적는다(상태는 안 바꾼다).

- **`done` 은 사용자가 그 창을 봐야 꺼진다.** 브라우저가 `/events` 로 `{"t":"seen","id":…}` 를 보내면 `idle` 로.
- **`waiting` 은 쳐다본다고 안 꺼진다.** 다음 훅이 와야 바뀐다.
- 약한 근거로 상태를 **올릴 수는 있어도 내릴 수는 없다** — 놓치는 것이 헛보는 것보다 나쁘다.
- 색 매핑(⑥)은 미정이다. 브라우저는 `status` 문자열을 받아 CSS 변수로 칠한다 — 색은 CSS 한 곳에 있다.

### 제목으로 읽기 (#38)

훅은 에이전트마다 협조가 필요하고, 그 협조가 없을 수 있다 — codex 의 훅은 계정 기능일 가능성이 있고(#15),
남이 만든 에이전트에는 아예 없다. 그래서 **훅이 한 번도 안 온 세션**에만 두 번째 근거를 쓴다.

에이전트는 바쁨을 **창 제목**(`OSC 0`/`1`/`2`)에 싣는다. 2026-09-08 실측:

| | 바쁠 때 | 한가할 때 |
|---|---|---|
| codex 0.147.0 | `⠹ palmar` (점자 스피너, 초당 ~12회) | `palmar` |
| Claude Code | `◐ Claude Code` (초당 ~1회) | `✳ …` |
| opencode | (제목을 한 번만 세우고 안 바꾼다) | 〃 |

**글자표는 만들지 않는다.** codex 는 점자, Claude Code 는 `◐◑` 다 — 표를 만들면 다음 에이전트에서
바로 깨지고, 그러면 훅으로 되돌아간 것과 같다. 대신 **제목이 계속 바뀌는 것만** 본다: 스피너는 정의상
계속 바뀐다.

- `TITLE_WINDOW_S` (3초) 안에 제목이 `TITLE_BUSY_N` (2) 번 이상 바뀌었으면 → `working`
- **돌다가** 멎으면 → `done`. 돌지도 않았으면 `idle` 그대로다 — 가만히 떠 있는 TUI(`vim` 같은)를
  "끝났다" 로 만들면 신호등이 늘 켜져 있게 된다.
- 두 번을 요구하는 것은 한 번짜리 제목 바꾸기를 거르기 위해서다. Claude Code 는 턴이 시작될 때
  제목을 그 턴의 말로 바꾼다.
- 이 길로는 **`waiting` 이 나오지 않는다.** 제목만으로는 "승인을 기다림" 과 "턴이 끝남" 이 같아 보인다.
  둘 다 사람을 부르는 상태이므로 `done` 으로 모은다 — 브라우저는 `waiting` 과 `done` 을 똑같이
  "나를 부른다" 로 다룬다.
- `done` 을 알아채는 데는 창 길이만큼(≈3초) 늦는다. 스피너가 멎었다는 것은 기다려 봐야 알 수 있다.
  `working` 은 0.2초 안에 잡힌다(실측).

### 제목을 안 쓰면 — 출력으로 읽기 (#22)

제목을 아예 안 세우는 에이전트가 있다. **실측(2026-09-08, `dev/probe-agent.py`): 어떤 것은
`window title (OSC 0/1/2): 0 changes` 였다.** 한 번 세우고 안 바꾸는 것도 있다.
**어느 쪽도 이름으로 알아보지 않는다** — 무엇이 오든 같은 규칙으로 읽는다.
되돌림은 **제목이 실제로 돈 적 없는 세션**에서 돈다. "제목을 세운 적 있나" 가 아니다 —
**셸이 프롬프트마다 제목을 세우는 것은 아주 흔하다**(WSL 의 bash 기본값 `\e]0;\u@\h: \w\a`).
그것을 "이 판은 제목으로 읽는다" 로 받으면 되돌림이 통째로 꺼지고, 셸 제목은 돌지 않으므로
**신호등이 영영 idle** 이다(사용자 보고 2026-09-08: `title='linux user@…'` 인데 `status=idle`.
macOS 의 맨 zsh 는 제목을 안 세워서 이 자리에서 안 보였다).
제목 층은 **한 번이라도 돈 것을 본 뒤에만** 주도권을 갖는다.

근거 둘을 묶는다:

| 보는 것 | 뜻 |
|---|---|
| `tcgetpgrp(master) == 셸 pid`, **그것이 달랐던 적이 있을 때만** | 앞에서 도는 것이 셸 자신 = **아무것도 안 돈다** → `idle` |
| 출력이 `OUT_MIN_S`(1초) 넘게 이어지고, 마지막 출력이 `OUT_QUIET_S`(5초) 안 | → `working` |
| 이어서 찍다가 멎었다 | → `done`. **찍은 적 없이 done 이 되지는 않는다** |

**`tcgetpgrp` 은 한 번이라도 달라진 것을 본 뒤에만 믿는다.** 직업 제어가 없는 셸에서는 자식이 셸과
같은 프로세스 그룹에 있어 이 값이 영영 셸을 가리킨다 — 그것은 "아무것도 안 돈다" 가 아니라
**알 수 없다** 는 뜻이다. 하드 게이트로 쓰면 **에이전트가 내내 찍고 있어도 idle** 이 된다
(실측 2026-09-08: 직업 제어 없는 셸에서 14초 내내 `idle`. 사용자가 WSL 에서 먼저 봤다).

**화면에 아무것도 안 남기는 출력은 일이 아니다.** 어떤 TUI 는 가만히 있어도 커서 관리 시퀀스를
계속 낸다 — **어떤 TUI 는 한가할 때 초당 10번, 똑같은 32바이트를 찍었다**(실측 2026-09-08:
15초에 147회, 전부 `ESC[?25l ESC[?7l ESC[?7h ESC[0m ESC[?12l ESC[?25h` 하나, 이스케이프를 걷어낸
내용은 0바이트). 그것을 활동으로 세면 **영원히 `working`** 이고 `done` 이 안 온다.

이것은 **화면을 읽는 것이 아니다.** 무엇이라고 썼는지는 안 본다 — 무엇이라도 썼는지만 본다.
조각이 `CONTENT_FAST`(512바이트)보다 크면 따지지 않고 내용이 있다고 본다(홍수 때 훑지 않으려고).

**한 번 찍고 마는 것은 일이 아니다.** 셸 프롬프트도, 끝난 `ls` 도 출력이다. `OUT_MIN_S` 가 그 둘을
걸러 내고, 프롬프트 검사가 무력한 셸에서는 이 값이 그 자리를 대신한다.

`tcgetpgrp` 이 이 층을 정직하게 만든다. 그것이 없으면 **프롬프트만 떠 있는 맨 셸이 "끝났다" 로
켜진다.** 실측: 맨 셸은 12초 내내 `idle` 이었고, 제목을 쓰는 에이전트는 제목 층이 그대로 이겼다.

**한계를 적어 둔다.** 아무것도 안 찍으면서 오래 생각하는 에이전트는 끝난 것과 구분되지 않는다.
이 근거로는 원리상 알 수 없다 — 훅과 제목이 있으면 그 둘이 이기는 이유가 이것이다.

제목 시퀀스는 **바이트에서 빼지 않는다** — alt 마커와 달리 그대로 브라우저의 xterm 으로 간다.
마지막 제목은 `Session.title` 로 나간다(`null` 이면 아직 아무도 안 세웠다).

## 판 (`v`)

`/events` 의 `hello` 가 **프로토콜 판**을 싣는다: `{"t": "hello", "v": 1, "daemon": "0.1.0", …}`.
`v` 는 이 문서의 판이고 `daemon` 은 패키지 판이다 — **둘은 따로 움직인다.** 겉이 바뀌어도 약속은
그대로일 수 있고, 그 반대도 있다.

- **올리는 때:** 프레임이나 필드의 **뜻**이 바뀌어 옛 페이지가 잘못 읽게 될 때.
- **안 올리는 때:** 필드를 더하기만 할 때. 모르는 필드는 무시하면 그만이다(위 `title`·`seq` 가 그랬다).
- 판이 다르면 브라우저는 **말하고 계속한다.** 막지 않는다 — 대개는 그래도 돌고, 막으면 고칠 방법
  (새로고침·데몬 재시작)까지 같이 막힌다.
- **한 곳에서 클론해 쓰는 동안은 어긋날 수가 없다** — 데몬과 페이지가 같은 커밋이다. 배포되고 나서
  달라진다: 브라우저가 캐시한 새 페이지가 안 올린 데몬을 만난다. 이 필드는 그때를 위한 것이다.

값은 `palmar/__init__.py` 의 `PROTOCOL` 과 `palmar/web/app.js` 의 `PROTOCOL` 둘이 짝이다.
`dev/dev-stub.py` 는 베껴 적지 않고 패키지에서 읽어 온다 — 베끼면 한쪽만 올라갔을 때 조용히 거짓말을 한다.

## 웹소켓 — 제어 채널 `/events?token=`

**페이지당 하나.** 브라우저당이 아니다 — 같은 브라우저의 탭 둘은 각자 자기 `/events` 를 연다.
⑪ 이 "창 둘이 서로 다른 캔버스를 본다" 를 요구하므로 이것이 맞는 단위다(2026-09-08 실측: 헤드리스
크롬 한 대에서 탭 둘이 각자 붙어 서로 다른 탭을 보고 있었고, 캔버스 이벤트는 둘 다에 갔다).
텍스트 프레임, JSON 한 줄씩.

서버 → 브라우저:
```jsonc
{ "t": "hello", "canvases": [Canvas…], "sessions": [Session…] }
                                                  // 붙자마자 전체. canvases 는 order 순, sessions 는 만든 순
                                                  // 이 한 프레임 안에서 모든 session.canvas 는 이 canvases 안에 있다
{ "t": "session", "s": Session }                  // 생겼거나 바뀌었다 (status·alt·cols·rows·agent·canvas·name)
{ "t": "gone", "id": "k3Jx…" }                    // 죽었다 (셸 종료·DELETE)
{ "t": "canvas", "c": Canvas }                    // 캔버스 하나가 생겼거나 이름이 바뀌었다
{ "t": "canvases", "cs": [Canvas…] }              // 순서가 바뀌었다 — order 순 전체
{ "t": "canvas_gone", "id": "Qm2p…" }             // 지워졌다. **바로 뒤에 canvases 가 따라온다**
```
브라우저 → 서버:
```jsonc
{ "t": "seen", "id": "k3Jx…" }                    // done → idle
```

**둘째 브라우저가 무엇으로 따라오는가** (2026-09-08 에 붙은 것):

| 무엇이 일어났나 | 가는 프레임 |
|---|---|
| 캔버스 만들기 | `canvas` 하나 |
| 캔버스 이름 바꾸기 | `canvas` 하나 |
| 캔버스 순서 바꾸기 | `canvases` 하나 |
| 캔버스 지우기 | `canvas_gone` **다음에** `canvases` |
| 세션이 캔버스를 옮김 | `session` 하나 |
| 세션 이름 바꾸기 | `session` 하나 |

- **세션이 옮겨 갈 때 새 메시지를 만들지 않았다.** `Session` 이 `canvas` 를 들고 있고 받는 쪽은 지금도
  `session` 을 통째로 갈아 끼운다 — 고칠 데가 없다. 이름도 같은 길로 온다.
- **만들기는 끝에 붙으므로 `canvas` 하나면 된다** — 다른 캔버스의 `order` 가 안 바뀐다.
- **지우기가 두 프레임인 이유:** 남은 것들의 `order` 를 0부터 다시 빈틈없이 매기기 때문에 목록 전체가
  바뀐다. **두 프레임의 순서는 계약이다** — `canvas_gone` 을 먼저 보내야 받는 쪽이 그 id 로 들고 있던
  탭 상태를 지운 다음 새 순서를 받는다.
- **순서 바꾸기를 `canvas` N 개로 쪼개지 않는 이유:** 받는 쪽이 중간에 잠깐 어긋난 탭 줄을 그린다.
- **캔버스 조작은 `/events` 로 보내지 않는다 — HTTP 로 간다.** 브라우저 → 서버는 여전히 `seen` 뿐이다.
  인증을 한 자리에 두고, `409`·`400` 을 돌려줄 길이 웹소켓에는 없기 때문이다.
- **낸 쪽도 방송을 되받는다** (HTTP 응답 한 번 + 방송 한 번). 브라우저는 id 로 멱등하게 반영하면 된다 —
  자기가 낸 것인지 가리려 하지 마라.
- **값이 실제로 달라졌을 때만 방송한다.** 같은 이름으로 다시 `PATCH` 하거나 `{}` 를 보내면 `200` 은
  돌아오지만 방송은 없다. 이름 입력칸이 글자마다 `PATCH` 를 날리는 식으로 짜이면 그때 방송이 폭주하기
  때문이다(기존 `on_hook`·`resize` 도 같은 결이다 — 안 바뀌면 안 쏜다). 받는 쪽은 HTTP 응답 하나만으로도
  최신이 되므로 이 생략에 기대도 된다.

## 웹소켓 — pane 채널 `/pty/<id>?token=&cols=&rows=&from=<offset>`

pane 당 하나. 여러 브라우저가 같은 pane 에 붙을 수 있다(각자 자기 오프셋). 모르는 `<id>` 는 업그레이드 전에
HTTP `404`. `cols`·`rows` 는 붙는 브라우저의 크기다 — 지금 크기와 다르면 `resize` 프레임을 받은 것처럼
적용한다(alt 면 그 크기로 흔든다). 없으면 크기를 건드리지 않는다.

**붙자마자 서버가 텍스트 한 프레임:**
```jsonc
{ "t": "hello", "offset": 48213, "alt": false, "replayed": 3072 }
```
- `alt` 가 `false` 면 그 뒤로 **링버퍼를 `from` 부터 재생**해 보낸다(바이너리). `from` 이 버퍼보다 앞이면
  있는 데부터. `replayed` 는 그 바이트 수. `offset` 은 재생 **뒤** 의 절대 오프셋.
  **브라우저의 다음 `from`** 은 `(offset − replayed) + 그 뒤 실제로 받은 바이트 수` 다(재생분 포함).
  `offset + 받은 바이트` 로 세면 재생분을 두 번 센다. 재생분도 `ack` 한다.
- `alt` 가 `true` 면 **재생하지 않고** `TIOCSWINSZ` 로 `(rows, cols-1)` → 50ms → `(rows, cols)` 를 넣는다.
  앱이 스스로 다시 그린다(스파이크 F). `replayed` 는 0. 흔든 뒤 `cols·rows` 는 흔들기 전 값이다.
- 그 뒤로 **바이너리 프레임 = PTY 바이트** (5ms 병합, 스파이크 D).
- 셸이 끝나면(exit·DELETE) close 프레임을 보내고 닫는다. `/events` 로는 `gone` 이 간다.

브라우저 → 서버:
| 프레임 | 뜻 |
|---|---|
| 바이너리 | 키 입력. 그대로 PTY 에 쓴다 |
| `{"t":"resize","cols":N,"rows":N}` | `TIOCSWINSZ`. **이것만이 행·열을 바꾼다** |
| `{"t":"ack","n":바이트수}` | 받아서 파싱까지 끝냈다. 흐름 제어 |

**흐름 제어 (스파이크 D 값):** 미확인 바이트 ≥ **100KB** 면 그 pane 의 PTY 읽기를 멈춘다(`remove_reader`).
≤ **10KB** 로 내려오면 다시 읽는다. 한 번 깨어날 때 최대 **256KB** 만 삼킨다. 브라우저가 여럿이면
가장 뒤처진 것 기준. **명령을 받는 파라미터는 없다** — 데몬이 `$SHELL` 을 박아 쓴다.

**링버퍼 (⑨):** pane 당 **256KB**, 절대 오프셋 `produced` 를 같이 든다. `ESC[?1049h` 를 보면 `alt=true`,
`ESC[?1049l` 을 보면 `alt=false`. **alt 안에서는 버퍼를 키우지 않는다** — 들어가기 전 바이트는 남긴다.
alt 가 바뀌면 `/events` 로 `session` 을 보낸다. **조각(alt 로 끊긴 구간) 수는 64개까지** — alt 를 그보다
자주 넘나든 뒤 재접속하면 256KB 미만이라도 오래된 조각이 재생에서 빠질 수 있다(#23. 계약과 코드가 같아야
Bun 으로 갈아 끼운다 — 이 상한을 없애고 인접 조각을 합치는 쪽으로 가도 된다. 사람이 정한다).

## zsh 래퍼 — `~/.palmar/zsh/`

**PATH 를 앞세우는 것만으로는 진다.** palmar 가 셸에 `PATH=~/.palmar/bin:$PATH` 를 넘겨도,
그 셸이 뜨면서 읽는 사용자 rc 가 나중에 자기 것을 다시 앞에 붙인다 — 실측: `~/.zshrc` 의
`export PATH="$HOME/.local/bin:$PATH"` 한 줄에 shim 이 밀려 `claude` 가 진짜 바이너리로 갔고
훅이 하나도 안 왔다(2026-09-07 통합에서 발견, 2026-09-08 원인 확인).

**셸이 zsh 이면 `ZDOTDIR` 로 감싼다.** 데몬이 `~/.palmar/zsh/` 에 `.zshenv`·`.zprofile`·`.zshrc`·
`.zlogin` 넷을 쓰고(0600), 자식 환경에 `ZDOTDIR=~/.palmar/zsh` 와
`PALMAR_USER_ZDOTDIR=<원래 ZDOTDIR 또는 $HOME>` 를 넣는다. 우리 rc 는 **사용자 것을 먼저 부른 뒤**
PATH 를 다시 앞세운다. **사용자 파일은 읽기만 한다.**

실측(2026-09-08, 격리된 가짜 HOME + 진짜 데몬):

| 상황 | `command -v claude` |
|---|---|
| 감싸지 않고 PATH 만 앞세움 | 진짜 바이너리 ← **진다** |
| ZDOTDIR 로 감쌈 | **shim** |
| 사용자 rc 없음 | shim |
| 사용자 rc 가 `ZDOTDIR=$HOME` 로 되돌림 | shim |
| 사용자 rc 가 PATH 를 통째로 덮어씀 | shim |
| 로그인 셸 `-l` | shim |
| **bash** (안 감쌌다) | 진짜 바이너리 ← **아직 안 됨** |

진짜 pane 에서 `claude -p` 를 띄우니 3초 만에 `working`/`agent=claude`/`UserPromptSubmit` 이 왔다.

**bash 도 감쌌다(2026-09-08).** `ZDOTDIR` 이 없으므로 `--rcfile` 로 물린다 —
데몬이 `~/.palmar/bash/bashrc`(0600)를 쓰고 자식을 `bash --rcfile <그 파일>` 로 띄우며
`PALMAR_USER_BASHRC`·`PALMAR_USER_BASH_PROFILE` 을 넘긴다. 우리 rc 가 로그인 셸이면
`.bash_profile` 을, 아니면 `.bashrc` 를 먼저 부르고 그 뒤에 PATH 를 되돌린다.
실측(2026-09-08, 진짜 데몬 · `SHELL=/bin/bash`): pane 안에서 `command -v claude` 가
`~/.palmar/bin/claude` 였다. **이게 WSL 에 중요하다** — 거기 기본 셸이 bash 다.

**fish 는 아직이다.** 그 셸에서는 PATH 경쟁에 질 수 있다 — 점이 회색에 머문다.

## shim — `~/.palmar/bin/claude`

데몬이 뜰 때 쓴다(0755). pane 을 만들 때 그 셸의 환경에 `PATH=~/.palmar/bin:$PATH`, `PALMAR_PANE=<id>`,
`TERM=xterm-256color`, `TERM_PROGRAM=palmar` 를 넣는다. 데몬을 띄운 터미널의 정체는 물려주지 않는다 —
`TERM_SESSION_ID`·`TERM_PROGRAM_VERSION`·`ITERM_SESSION_ID`·`TMUX`·`TMUX_PANE` 을 뺀다(Terminal.app 에서 띄우면
pane 의 zsh 가 `/etc/zshrc_Apple_Terminal` 을 타서 "Restored session:" 을 찍고 띄운 터미널과 히스토리 파일을
공유했다 — 2026-09-07 통합 실측 1회).
**띄운 쪽 에이전트의 정체도 뺀다:** `CLAUDECODE`·`CLAUDE_*`·`CODEX_*`·`AI_AGENT` 로 시작하는 것 전부.
**예외는 `CLAUDE_CONFIG_DIR` 하나** — 사용자가 자기 셸에 직접 두는 설정이라 pane 에서도 그대로여야 한다.
(2026-09-08 에 넓혔다. 옛 목록은 `CLAUDECODE`·`CLAUDE_CODE_*`·`CODEX_COMPANION_*` 셋이었고 적힌 뜻보다 좁아,
진짜 pane 에 붙어 `printenv` 를 돌리니 `AI_AGENT`·`CLAUDE_EFFORT`·`CLAUDE_PID`·`CLAUDE_PLUGIN_DATA`·
`CLAUDE_OFFICE_API_URL` 다섯이 그대로 넘어가 있었다 — pane 환경변수 55개 중 다섯. 넓힌 뒤 50개, 다섯 다 없다.
**안 잰 것:** 저 다섯이 실제로 중첩 `claude` 의 시작을 바꾸는지는 안 쟀다. 재서가 아니라 규칙으로 뺀다.)
pane 마다 `~/.palmar/run/<id>.json` (0600) 을 쓴다:

```jsonc
{ "hooks": {
    "SessionStart":      [{ "hooks": [{ "type": "http", "url": "http://127.0.0.1:8801/hook/claude?pane=<id>&token=<token>" }] }],
    "UserPromptSubmit":  [ … 같은 모양 … ],
    "PermissionRequest": [ … ],
    "Notification":      [ … ],
    "Stop":              [ … ],
    "SessionEnd":        [ … ] } }
```

shim 자체:
```sh
#!/bin/sh
# palmar shim: attaches hooks to a claude started inside a palmar terminal. Nothing else.
d=$(cd "$(dirname "$0")" && pwd)
new=
IFS=:
for e in $PATH; do
  case "${e%/}" in
    "$d") ;;                       # 자기 디렉터리 — 뒤 슬래시 있든 없든 뺀다 (고정 문자열 비교)
    *) new="${new:+$new:}$e" ;;
  esac
done
unset IFS
PATH=$new
real=$(command -v claude) || { echo "palmar: claude not found on PATH" >&2; exit 127; }
f="$HOME/.palmar/run/$PALMAR_PANE.json"
[ -n "$PALMAR_PANE" ] && [ -r "$f" ] && exec "$real" --settings "$f" "$@"
exec "$real" "$@"
```
- 자기 디렉터리는 **고정 문자열**로 견주고 뒤 슬래시 철자도 함께 뺀다(#12). 옛 `grep -vx "$d"` 는 `$d` 를
  정규식으로 봐서 `.palmar` 의 `.` 가 아무 글자나 맞았고(예: PATH 의 `/Xpalmar/bin` 이 잘못 빠짐),
  `/…/.palmar/bin/` 처럼 뒤 슬래시가 붙은 철자는 못 빼 `command -v claude` 가 자기(shim)를 다시 골라 무한 exec 했다.
- `--settings` 는 **병합**이다(스파이크 E). 사용자 훅을 지우지 않는다.
- pane 이 죽으면 그 `<id>.json` 을 지운다. 데몬이 뜰 때 `run/` 의 고아 `.json` 을 지운다.
- codex·opencode shim 은 **아직 없다**(⑧ 미정). `claude` 만.
- **알려진 문제(미해결, 2026-09-07 실측):** 사용자 rc 파일이 `PATH` 앞에 다른 디렉터리를 다시 세우면 shim 이
  진다. 이 기계의 `.zshrc` 는 `export PATH="$HOME/.local/bin:$PATH"` 를 갖고 있어 pane 안에서 `command -v claude`
  가 `~/.local/bin/claude` 였다(`~/.palmar/bin` 은 PATH 5번째, `~/.local/bin` 은 4번째). 즉 지금 구조로는 이
  사용자에게 훅이 안 붙는다. 어떻게 풀지는 정하지 않았다 — 판단 재료는 데몬 보고서(#22)에 있다.

## 위치·크기·이름·캔버스 소속 — 어디에 있는가

<!-- 옛 제목은 "위치·크기 — 데몬에 없다" 였다. palmar/web/app.js 머리말이 그 이름으로 가리키고 있어
     "위치·크기" 를 제목에 남겨 둔다. 이제 이 절은 데몬에 있는 것도 같이 적는다. -->

| 무엇 | 어디 | 언제까지 사는가 |
|---|---|---|
| 창의 좌표·크기·z 순서 | **브라우저 `localStorage`** (`palmar-tiles`, session `id` 키) | 그 브라우저가 지울 때까지 |
| 캔버스 목록·`name`·`order` | **데몬 메모리** | 데몬이 사는 동안 |
| 세션의 `canvas`·`name` | **데몬 메모리** (`Session` 안) | 그 세션이 사는 동안 |
| 지금 보고 있는 탭 · 목록 그룹 접힘 · 미니맵 | **브라우저에만** (아래 "없는 것") | 그 브라우저 안에서 |

창의 좌표가 `localStorage` 에 있는 것은 전부터 그랬고 **③(어디에 두는가)이 미정이라 임시다** —
이건 결정이 아니라 지금 도는 데 필요한 최소다. 데몬은 pane 의 `cols·rows` 만 안다.

**아무것도 디스크에 안 쓴다.** 데몬이 다시 뜨면 캔버스도 이름도 없다 — 그때는 셸 pane 도 다 죽으니
(⑦=b, 핸드오프 없음) 남길 대상 자체가 없다. 좌표는 `localStorage` 에서 살아남지만 키가 session `id`
라서 같이 쓸모가 없어진다. **그래서 실질적으로는 셋 다 데몬보다 오래 살지 못한다** — 빈 캔버스만
자기 안의 세션들보다 오래 살고, 그것도 데몬까지다.

**③ 은 여기서 정하지 않았다.** 새로 온 두 줄에 대해 말할 수 있는 것은 이것뿐이다 —
**③ 이 어느 쪽으로 정해지든 캔버스 소속과 이름의 "돌고 있는 사본" 은 데몬에 있어야 한다.**
둘째 브라우저가 이름 바꾸기·순서 바꾸기·캔버스 이동을 봐야 하는데(⑪) `localStorage` 는 남에게
방송할 수 없기 때문이다. **③ 이 정하는 것은 그것을 파일로도 남기느냐, 그리고 좌표는 어디에 두느냐다.**

**PROVISIONAL — 사람이 볼 것.** ⑫ 에는 "이름은 자리와 같은 곳에 저장된다(③ 가 정해지면 따라간다)"
라고 적혀 있다. 그 문장을 글자 그대로 따르면 이름이 `localStorage` 로 갈 수도 있는데, 그러면 위
이유로 둘째 브라우저에서 이름이 안 보인다. 그래서 **돌고 있는 사본은 데몬**에 두고 **저장 위치는
③ 에 그대로 넘긴다.** ⑫ 를 뒤집은 것이 아니라 ⑫ 가 아직 안 정해진 ③ 에 매여 있는 것이고,
사람이 ③ 을 정할 때 이 절도 같이 정해진다.

- **"↗ off" 배지(화면 밖 표시).** 미니맵과 **같은 스크롤 경로에 있다** — 그래서 같은 규칙을 받는다.
  자리는 좌표 스토어에서 읽고 DOM 에 묻지 않는다. (2026-09-08 통합에서 이 자리가 창마다
  `offsetLeft/Top/Width/Height` 를 읽어 스크롤 한 묶음마다 창 수 × 4번의 레이아웃을 강제하고 있었다 —
  창 5개에 20번을 실측하고 고쳤다. 캔버스는 무한히 자라므로(⑩) 그 값은 창 수를 따라 늘어난다.)
  **배지 하나를 뒤집자고 왼쪽 목록을 다시 짓지도 않는다** — 그 판은 스크롤 6초에 목록 전체를 60번쯤 다시
  지었고(2026-09-08 실측: 창 16개에 62·62·60, 3회) 매번 모든 `.ses` 행이 부서져 **레일에 잡아 둔 글자 선택이
  사라졌다.** 지금은 바뀐 행의 `↗ off` 하나만 제자리에서 뒤집는다(같은 조건에서 0·0·0).
- **탭 줄을 어떻게 고쳐 그리는가.** 계약은 `canvas`·`canvases`·`canvas_gone` 셋과 "점은 계산이다" 까지고,
  그것으로 줄을 **다시 짓느냐 고치느냐**는 브라우저의 것이다. 지금 구현은 **고친다** — 살아 있는 탭 DOM 을
  다시 쓰고 글자·점·고름만 제자리에서 바꾸며, 자리 옮기기(순서)만 끌기·이름 고치기 중에 미룬다.
  다시 짓던 판은 두 군데서 아팠다(둘 다 2026-09-08 실측, 헤드리스 크롬 152):
  세션 프레임 하나가 끌던 탭을 DOM 에서 떼어 내 **같은 탭이 둘이 되고**(20 → 21, id 중복 1) 놓을 때
  `POST /api/canvases/order` 가 `409` 로 튕겨 순서 바꾸기가 사라졌고, 이름을 고치는 동안 줄을 통째로 미뤄
  **데몬이 `waiting` 인데 점이 5초 넘게 꺼져 있었다.** 점은 탭이 지는 유일한 신호다(⑪).
  **현재 탭을 화면 안으로 끌어다 놓는 것도 브라우저의 것이다** — 탭 20개면 줄이 넘치는데(`#tabs`
  clientWidth 1112 vs scrollWidth 2755) 스크롤바를 감춰 뒀다. 현재 탭이 바뀐 순간에만 `scrollIntoView` 한다.
- **왼쪽 목록 그룹의 접기·펴기.** 그 브라우저의 취향이지 세션의 성질이 아니다. 테마와 같은 자리다.
  **묶는 기준(캔버스냐 상태냐)도, "기다리는 것은 접어도 안 숨는다" 는 보장도 여기 없다** — 둘 다
  브라우저의 것이고 `decisions.md` ⑪ 에 적혀 있다. 데몬이 하는 일은 `session.canvas` 와 `status` 를
  정확히 보내는 것까지고, 그것으로 목록을 어떻게 묶고 무엇을 남기는지는 받는 쪽이 정한다.
  갈아 끼울 구현(② Bun)에 요구되는 것은 필드지 이 규칙이 아니다.
- **`DELETE /api/sessions/<id>` 의 `404` 를 브라우저가 어떻게 읽는가.** 계약은 "없으면 `404`" 까지다
  (2026-09-08 실측: 두 브라우저가 거의 동시에 닫으면 정확히 `204` 하나 · `404` 하나). 지금 구현은
  그 `404` 를 **실패로 안 본다** — 남이 먼저 닫았고 사용자가 시킨 결과는 이미 나 있으니 조용히
  지나간다. 지우는 것은 여전히 `gone` 하나뿐이라 지우는 길이 둘로 갈리지 않는다.
- **지금 보고 있는 탭.** 브라우저마다 다르다 — 창 둘이 서로 다른 캔버스를 볼 수 있어야 한다.
  그래서 데몬에 "현재 캔버스" 가 없고, 그래서 `POST /api/sessions` 가 `canvas` 를 실어 보낸다.
  **보고 있던 탭이 `canvas_gone` 으로 사라지면 어디로 가는지도 브라우저의 것이다** — 데몬은 두 프레임을
  순서대로 보낼 뿐이고 그 뒤는 안 묻는다. 지금 구현은 `order` 가 가장 앞인 캔버스로 간다(2026-09-08 실측:
  보고 있던 탭을 지웠을 때 두 브라우저 다 남은 첫 탭으로 갔다). 캔버스는 0개가 될 수 없으므로
  (마지막 하나는 `409`) **갈 곳은 언제나 있다.** 다른 구현이 다르게 골라도 계약은 안 깨지지만,
  두 브라우저가 서로 다른 곳에 서게 되므로 여기 적어 둔다.
- **캔버스가 하나일 때 탭 줄을 숨길지**(⑪ 의 열린 항목), 탭 줄의 생김새, 끄는 동안의 애니메이션,
  이름 없는 캔버스의 이름표를 무엇으로 만들지(⑪: "폴더에서 따는지 사람이 짓는지" 는 아직 미정이다 —
  프로토콜은 `name: null` 만 나르고 글자는 브라우저가 만든다).

여기 없는 것은 **못 만든 것이 아니라 데몬이 몰라도 되는 것**이다. 데몬이 알면 진실이 둘로 갈리고
갈아 끼울 때(② Bun) 같이 옮겨야 한다.

## 스파이크와 다른 점

스파이크 D 는 `/pty?cols=&rows=` 에 붙으면 셸을 새로 띄웠다. 제품은 **세션을 먼저 만들고(`POST /api/sessions`)
그 id 로 붙는다** — 탭을 닫아도 세션이 살아야 하기 때문이다. 스파이크의 흐름 제어 상수·병합 시간·
`Frame`/`read_frame` 은 그대로 가져온다. 스파이크 G 의 `Pane.since(offset)` 이 재생 로직이다.
