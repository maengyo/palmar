# 사용자가 알려준 것 — 무엇이었고, 어떻게 됐나

**왜 이 파일이 있나.** 2026-09-18 에 사용자가 물었다: *"내가 말한 버그는 다 기록하고 결과도 다
적고 있는거지?"* 답은 **아니오** 였다. 고친 것은 커밋 메시지와 코드 주석과 `docs/` 에 들어갔지만,
**못 고친 것·재현 안 된 것·보류한 것은 대화 안에만** 있었다. 대화가 끝나면 사라진다.

여기는 **사용자가 겪은 것**만 적는다. 설계 결정은 `decisions.md`, 할 일은 `backlog.md`.
한 줄 규칙: **재현했는가 · 원인이 무엇이었는가 · 지금 어떤 상태인가.** 추측은 추측이라고 적는다.

## 열려 있는 것

### 그룹이 여러 번 움직이면 계단식으로 어긋난다 — 재현 실패, 계측기 넣어둠

- **증상** (2026-09-17) 좌우로 나란하던 그룹 멤버가 드래그를 거듭할수록 조금씩 어긋난다.
- **세 가지 가설을 재서 전부 틀렸다.** 마지막 것: `persist()` 가 `offsetLeft` 를 되읽어서 배율
  1.125 에서 창마다 반올림이 갈린다 → **배율 1 · 1.125 · 1.25 · 1.5 에서 전부 동일하게 반올림**.
  재현도 실패 — 뷰포트 안팎을 오가는 긴 드래그 20회, 다른 창 위를 지나는 드래그 14회.
- **지금:** `localStorage.setItem('palmar.watchgroups','1')` 를 켜면, 멤버 구성이 그대로인데
  모양만 바뀐 순간의 **스택**을 콘솔에 찍는다. 한쪽 멤버만 움직인 함수 이름이 거기 나온다.
- 곁들여 위생 작업 둘(드래그 델타 정수 반올림 · 놓을 때 화면 되읽지 않기)이 들어갔으나
  **이것이 고쳤다는 보장은 없다.**

### aelix 는 "나를 기다림"(호박색)을 켤 수 없다 — 구조적 한계

- **증상** (2026-09-18) aelix 가 승인 선택을 기다리는 동안 계속 초록(일하는 중).
- **원인:** aelix 에 붙은 층이 ④(출력 활동) 하나뿐이다. `--doctor` 실측:
  `this pane sets no window title` — ③도 비어 있고, palmar 의 훅 shim 은 `claude` 하나뿐이라
  ①도 비어 있다. ④가 보는 것은 "바이트가 나오느냐" 뿐이라, 메뉴를 그리며 기다리는 것과
  일하며 찍는 것이 **바이트만으로는 같다.**
- **답이 될 수 있는 것:** ⓐ aelix 에 훅을 붙인다(정확) · ⓑ 대체 화면 안에서 **직전과 똑같은
  출력**은 진전이 아니라고 본다(부정확하지만 불은 움직인다. 빨강이 호박색 몫을 대신하게 됨).
- 답변 후 빨간불은 뜬다(2026-09-18 확인). 남은 것은 기다림 하나.

### 흩어진 터미널을 다시 모으는 버튼 — 기준 미정

- **요청** (2026-09-17) 장난으로 아주 멀리 떼어 놓은 창들을 어느 정도 가깝게 정리하는 버튼.
  그룹은 안 무너뜨리고.
- **막힌 곳:** 기준을 사용자가 골라야 한다. ⓐ 왼쪽 위부터 격자로 다시 채우기 ⓑ 상대 배치는
  살리고 간격만 좁히기. "창은 놓아둔 자리에 있는다" 와 부딪히므로 **명시적으로 누를 때만.**

### 설치한 앱을 작업표시줄에 고정하면 아이콘이 빈 종이가 된다 — 재현 못 함

- **증상** (2026-09-18) 브라우저에서 설치한 뒤 작업표시줄에 고정하면 로고가 빈 종이 모양으로
  바뀐다. **누르면 palmar 는 제대로 열린다** — 대상은 맞고 그림만 틀렸다.
- **palmar 쪽은 재봤고 맞다.** `icon-192.png`·`icon-512.png` 는 선언한 크기 그대로의 RGBA PNG 고,
  `.html` 만 키를 요구하므로 아이콘은 키 없이 나간다. 매니페스트도 정상.
- **고친 것 하나:** 매니페스트에 `id` 가 없었다. 그러면 브라우저가 `start_url` 을 앱의 정체로
  삼는데 거기엔 **키가 들어 있다.** 키를 돌리거나 포트가 바뀌면 같은 palmar 가 **두 번째로**
  설치되고, 누가 고정해 둔 바로가기는 옛것을 가리킨 채 남는다. 이번 증상의 원인이라는 증거는
  없다 — 그냥 명백히 틀려 있던 것이고, 아이콘 정체와도 닿아 있다.
- **남은 것:** 윈도우 셸의 아이콘 추출은 여기서 재볼 방법이 없다. 다음에 볼 것 — 설치 직후
  시작 메뉴의 아이콘은 맞는지(맞다면 고정 단계만의 문제), 그리고 `chrome://apps` 에서 palmar 의
  아이콘이 제대로 보이는지.
