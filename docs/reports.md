# 사용자가 알려준 것 — 무엇이었고, 어떻게 됐나

**왜 이 파일이 있나.** 2026-09-18 에 사용자가 물었다: *"내가 말한 버그는 다 기록하고 결과도 다
적고 있는거지?"* 답은 **아니오** 였다. 고친 것은 커밋 메시지와 코드 주석과 `docs/` 에 들어갔지만,
**못 고친 것·재현 안 된 것·보류한 것은 대화 안에만** 있었다. 대화가 끝나면 사라진다.

여기는 **사용자가 겪은 것**만 적는다. 설계 결정은 `decisions.md`, 할 일은 `backlog.md`.
한 줄 규칙: **재현했는가 · 원인이 무엇이었는가 · 지금 어떤 상태인가.** 추측은 추측이라고 적는다.

## 열려 있는 것

### 그룹이 여러 번 움직이면 계단식으로 어긋난다 — 재현 실패, 계측기 넣어둠

- **증상** (2026-09-17) 좌우로 나란하던 그룹 멤버가 드래그를 거듭할수록 조금씩 어긋난다.
- **세 가지 가설을 재서 전부 틀렸다.** 마지막 것: `persist()` 가 `offsetLeft` 를 되읽어서 배율
  1.125 에서 창마다 반올림이 갈린다 → **배율 1 · 1.125 · 1.25 · 1.5 에서 전부 동일하게 반올림**.
  재현도 실패 — 뷰포트 안팎을 오가는 긴 드래그 20회, 다른 창 위를 지나는 드래그 14회.
- **지금:** `localStorage.setItem('palmar.watchgroups','1')` 를 켜면, 멤버 구성이 그대로인데
  모양만 바뀐 순간의 **스택**을 콘솔에 찍는다. 한쪽 멤버만 움직인 함수 이름이 거기 나온다.
- 곁들여 위생 작업 둘(드래그 델타 정수 반올림 · 놓을 때 화면 되읽지 않기)이 들어갔으나
  **이것이 고쳤다는 보장은 없다.**

### aelix 는 "나를 기다림"(호박색)을 켤 수 없다 — 정해졌고, 절반만 답한다

- **증상** (2026-09-18) aelix 가 승인 선택을 기다리는 동안 계속 초록(일하는 중).
- **원인:** 붙은 층이 ④(출력 활동) 하나뿐이다. `--doctor` 실측: `this pane sets no window title`.
  ④가 보는 것은 "바이트가 나오느냐" 뿐이라, 메뉴를 그리며 기다리는 것과 일하며 찍는 것이 같다.
- **정한 것** (2026-09-19, 사용자): **대체 화면 안에서 직전과 똑같은 출력은 진전이 아니다.**
  화면을 읽는 게 아니라 직전과 같은지만 본다 — 커서 제어만 거르던 기존 규칙의 한 칸 확장이다.
  alt 안에서만이라 `while true; do echo x; done` 같은 셸 루프는 그대로 일로 센다.
- **절반의 진실임을 알고 쓴다.** 빨강은 "끝남" 이라 쳐다보면 꺼지는데, 승인 프롬프트는 쳐다본다고
  사라지지 않는다. 정확한 길은 여전히 aelix 에 훅을 붙이는 것뿐이다.

### 흩어진 터미널을 다시 모으는 버튼 — 기준 정해짐

- **요청** (2026-09-17) 아주 멀리 떼어 놓은 창들을 어느 정도 가깝게 정리하는 버튼. 그룹은 안 무너뜨리고.
- **정한 것** (2026-09-19, 사용자): **상대 배치는 살리고 간격만 좁힌다.** 왼쪽 위 격자로 몰아넣는
  안은 안 썼다 — "창은 놓아둔 자리에 있는다" 와 가장 덜 부딪히는 쪽이다. **명시적으로 누를 때만.**

### 시험이 길게 돌 때 브라우저 기동이 가끔 시간 초과한다 — 도구 쪽

- **증상** 전체 스위트(약 8분) 안에서 임의의 브라우저 시험 하나가
  `cdp.py` 의 `WS(...)` 에서 `socket.timeout` 으로 죽는다. **혼자 돌리면 통과한다.**
  2026-09-18 하루에 네 번 봤고, 매번 다른 시험이었다(`InstallableAsAnApp`, `NoTitleBar`,
  `Shortcuts` …).
- **무엇이 아닌가:** 제품 결함이 아니다. 같은 트리가 바로 앞뒤로 458개 전부 통과한다.
- **왜 적어두나:** 초록을 한 번 더 돌려서 확인하는 데 매번 8분이 든다. 그리고 진짜 실패를
  "또 그거겠지" 로 넘길 위험이 있다 — 그게 이 항목의 진짜 값이다.
- **다음 수:** `cdp.py` 의 `Browser.start` 가 DevTools 소켓을 기다리는 시간과 재시도를 본다.
  기동 자체는 40초를 기다리는데(`end = time.time() + 40`), 그 뒤 `WS` 연결은 한 번만 시도하고
  소켓 타임아웃은 10초다.
