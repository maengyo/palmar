## [P0][spike] pane 출력을 스트리밍할 수 있는가

**이 답이 아니면 palmer 는 성립하지 않는다.** 그래서 첫 번째다.

`pane.read` 로 화면을 읽는 건 확인했다(`format:"ansi"` 로 이스케이프까지). 하지만 그건
**스냅샷**이다. 살아 있는 터미널을 그리려면 바뀌는 걸 계속 받아야 하고, 폴링으로 때우면
입력이 늦거나 CPU 를 태운다.

확인할 것:
- `events.subscribe` 가 pane 출력 변화를 주는가, 수명주기 이벤트만인가
- `pane.wait_for_output` 이 롱폴링으로 쓸 만한가 — 반환까지 얼마나 걸리고 무엇을 주는가
- pane 의 `revision` 이 커서 역할을 하는가 (마지막으로 본 이후만 받기)
- 다 아니면: 얼마나 자주 `pane.read` 를 불러야 즉각적으로 느껴지고, 그때 CPU 는 얼마인가

**측정으로 답한다.** 숫자를 `docs/herdr-api.md` 에 적는다.
스트리밍이면 다리는 정말 얇아지고, 폴링이면 **"가볍게"라는 전제를 다시 봐야 한다.**

## [P0][spike] agent_status 가 실제 에이전트에서 믿을 만한가

`agent_status` 가 pane 객체에 있는 건 확인했다. 그런데 평범한 셸에서는 `"unknown"` 이었다.
**실제 에이전트에서 어떤 값이 언제 오는지는 모른다.**

확인할 것:
- claude 를 pane 에서 돌리고 턴을 하나 보낸다. 언제 무엇으로 바뀌는가
- **`working` 과 `blocked` 가 실제로 갈리는가** ← 핵심. 승인 프롬프트에서 `blocked` 가
  안 뜨면 "나를 기다리는 세션"을 못 찾고, 그러면 이 도구의 존재 이유가 없다
- codex·opencode 도 같은가 / 값이 즉시 오는가
- herdr 가 어떻게 감지하는지(`server.agent_manifests`) — 훅인지 프로세스 검사인지에 따라
  신뢰도가 다르다

참고: 네 CLI 의 훅·이벤트 프로토콜 실측 기록이
[polycanv/docs/research/cli-status-hooks.md](https://github.com/maengyo/polycanv/blob/main/docs/research/cli-status-hooks.md)
에 있다. herdr 가 놓치는 게 있으면 그걸로 근거를 댈 수 있다.

## [P1] palmer 서버 — herdr 소켓과 브라우저 사이의 얇은 다리

브라우저는 유닉스 소켓을 못 연다. 그래서 다리가 필요하고, 하는 일은 그것뿐이다.

- 웹소켓을 받아 herdr 소켓으로 중계
- 정적 파일(캔버스 UI) 서빙
- **`127.0.0.1` 에만 붙는다**

하지 않을 일: 세션 상태 캐시(herdr 가 원본이다), 인증(지금은 로컬 전용 전제).

**스파이크 ① 이 먼저다** — 스트리밍이냐 폴링이냐로 다리의 모양이 달라진다.

## [P1] 캔버스 — 자유 배치와 크기 조절

palmer 가 존재하는 이유. 터미널이 **놓아둔 자리에 그대로** 있고, 겹칠 수 있고,
크기를 바꿀 수 있다.

- pane 하나 = 캔버스 위의 창 하나. xterm.js 로 그린다
- 제목 줄을 끌면 이동, 모서리를 끌면 크기 조절
- **본문은 터미널의 것이다** — 글자를 고르려고 끄는데 창이 따라오면 안 된다
- **캔버스 밖으로 나가지 않는다.** 자유 배치는 아무 데나 둘 수 있다는 뜻이지
  잃어버릴 수 있다는 뜻이 아니다

**줌은 브라우저가 공짜로 준다.** 자체 줌을 만들기 전에 그걸로 충분한지 먼저 본다.

## [P1] 신호등 — 창마다 working / blocked / idle

"어느 세션이 나를 기다리는가"에 답하는 부분.

- **색이 곧 의미다.** 초록·호박·회색을 다른 데 쓰지 않는다
- **이모지를 쓰지 않는다** — 폭이 터미널·폰트마다 달라 배치가 밀린다
- **`blocked` 는 봐도 안 꺼진다.** 승인 프롬프트는 쳐다본다고 사라지지 않는다

스파이크 ② 뒤에 그린다. 값이 못 미더우면 색을 칠해봐야 거짓말이 된다.
