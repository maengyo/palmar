# 정한 것, 뒤집은 것, 일부러 안 정한 것

## 정한 것 (근거 있음 — 뒤집으려면 근거를 대라)

**런타임은 우리 것이다.** (2026-09-07, 사용자 결정) PTY·세션 유지·상태 수신을 palmar 가 직접
갖는다. 남의 멀티플렉서(herdr·tmux·zellij) 위에 얹지 않는다.
이유는 "기능이 비슷해도 남의 프로그램에 종속되는 것은 별로다" 다.
뒷받침하는 사실은 herdr 스파이크에서 나왔다 — 프로토콜 번호가 0.7.0=14 → 0.8.2=20 으로 오르고
master 는 22 인 것, 스키마에 있는데 구현 안 된 것(`pane_output_changed`, 업스트림은 "계획 없음"),
`pane.wait_for_output` 이 서버 내부 100ms 폴링인 것, 화면 정규식 감지가 codex 대화상자를 놓친 것.
값은 직접 갖는 것의 범위로 낸다: **PTY·바이트·훅·자리, 그 이상은 아니다.**

**터미널 에뮬레이션은 브라우저에서 한다.** polycanv 가 서버(pyte)에서 하다가 부하에서 tmux 의
8배 CPU 를 썼다(polycanv 실측 2026-08-20, `seq 1 200000` 에서 CPU 1.50s vs 0.18s; 벽시계는
1.84s vs 1.14s). xterm.js 가 브라우저에서 하면 서버는 바이트만 옮긴다.
**둘 다 2026-09-07 에 쟀다**(⑤ 와 `own-runtime.md` 스파이크 D) — 서버는 pane 8개 전부 최대
출력에서 CPU 98% · RSS 31MB, 브라우저는 같은 조건에서 60fps 를 지켰다. 재접속 복원을 위해 서버에 헤드리스 에뮬레이터를
두는 것(VS Code 방식)은 같은 비용을 다시 내는 것이라 기본값이 아니다 — ⑨ 에서 다른 길을 먼저 잰다.

**상태는 CLI 의 훅/이벤트로 받는다.** claude·codex·qwen 은 `PermissionRequest`/`Stop` 훅,
opencode 는 SSE. polycanv 가 claude·codex 는 TUI 에서 훅 발화까지 실측했고(2026-08-19),
opencode 는 `/event` 접속까지, qwen 은 `SessionStart` 까지만 확인했다.
이번에 Claude Code 2.1.259 에서 `PermissionRequest` 가 대화상자와 같은 순간에, 승인·질문 구분 없이
오는 것을 다시 실측했다. 화면 정규식은 쓰지 않는다 — herdr 에서 실제로 틀렸다.
(단, codex 의 터미널 타이틀처럼 **CLI 가 상태를 쓰라고 만든 채널**은 정규식이 아니라 이벤트로 본다 — ⑧.)

**세션은 UI 보다 오래 산다.** polycanv #21 이 "이것이 제품이다" 라고 적었다.
그 이슈가 그린 모양은 **직접 데몬을 갖는 것**이었고("a daemon owns the PTYs… the UI becomes a
client that attaches and detaches"), 멀티플렉서에 얹는 길은 거기서 이미 거절됐다("it concedes the
premise that this works without a multiplexer"). herdr 로 간 것은 그 요구가 아니라 "직접 만들면
몇 달" 이라는 2026-09-01 의 견적 때문이었다.
master fd 를 마지막으로 닫는 순간 자식은 SIGHUP 을 받으므로(조사 에이전트의 macOS 로컬 실행,
Linux 는 커널 문서) 누군가 fd 를 들고 있어야 한다. 데몬 재시작 때 fd 를 다음 프로세스에 넘길 수
있다는 것은 실측했다(`docs/own-runtime.md` 스파이크 A) — 무엇을 살릴지는 ⑦ 에서 정한다.

**palmar 는 셸만 연다.** (2026-09-07, 사용자) 폴더를 고르고 버튼을 누르면 그 경로의 셸이 캔버스에
뜨고, 그 안에서 무엇을 돌릴지는 사용자가 정한다. **palmar 는 도구 목록을 갖지 않는다** — claude 를
어떻게 실행하는지 몰라도 된다. polycanv 의 `tools.toml` 이 통째로 사라진다.

**훅은 palmar 가 붙인다 — PATH shim 으로.** (2026-09-07 저녁, 사용자. 같은 날 오전의 "사용자가
한 번 설치한다" 를 뒤집었다) palmar 가 여는 셸의 PATH 맨 앞에 `~/.palmar/bin` 을 둔다. 거기 `claude`
껍데기가 있고, 사용자가 `claude` 를 치면 껍데기가 진짜 `claude --settings /tmp/palmar/<pane>.json` 을
exec 한다. pyenv·rbenv·ccache·Nix `makeWrapper` 가 쓰는 방식이다.

- **사용자는 아무것도 안 한다.** 설치는 한 줄로 돌아온다(원칙 7).
- **사용자 설정 파일을 안 건드린다.** 옛 원칙("사용자의 설정 파일을 고치지 않는다")이 그대로 산다.
- **짝짓기는 URL 에 있다.** settings 파일이 pane 마다 다르고 `?pane=<id>` 가 붙는다. 환경변수도
  `http` 헤더도 필요 없다 — 오전에 "미확인" 이던 그 문제가 사라진다.
- **훅은 무슨 일이 있어도 0 으로 끝난다** — palmar 가 안 떠 있으면 조용히 넘어간다. 이건 그대로.
- **어느 셸이든 된다.** rc 파일을 안 만지니 zsh·bash·fish·WSL 이 같다.

**전제를 실측했다(스파이크 E, `spikes/2026-09-07/shim/`).** `claude --settings X` 는 다른 층의 훅을
**대체하지 않고 병합한다** — 프로젝트 훅과 `--settings` 훅이 `SessionStart`·`UserPromptSubmit`·`Stop`
세 이벤트 모두에서 둘 다 발화했다(Claude Code 2.1.263, 1회). `http` 훅 타입도 실제로 받았다 —
`UserPromptSubmit`·`Stop` 은 왔고 **`SessionStart` 는 안 왔다**(command 타입은 왔다). 1회 관측이라
재확인 대상이지만, 상태에 쓰는 세 이벤트에는 걸리지 않는다.

**비켜 가는 경우.** `command claude`·절대 경로·`npx` 로 껍데기를 우회하거나, palmar 밖에서 띄운
`claude` 는 훅이 없다. 그때 palmar 는 **회색 = 모름** 으로 두고 알려 준다(⑥). 이 경우의 대안으로
OpenCove 가 쓰는 **세션 파일 감지**(에이전트가 디스크에 남기는 기록을 읽는다)를 #20 에서 같이 본다.

**codex 는 껍데기가 `-c` 로 설정을 넘기거나 터미널 타이틀을 읽는다** — PTY 를 palmar 가 소유하니
타이틀 변경은 이미 우리 손에 온다(⑧ 에서 정한다). **opencode 는 설치할 것이 없다.**

프로젝트마다 파일을 심는 길(cate 방식, `.claude/settings.local.json`)은 여전히 아니다 — 터미널이
여러 프로젝트에 흩어지고, `cd` 하면 벗어나고, codex 신뢰가 해시 단위라 프로젝트마다 다시 승인이다.
껍데기는 프로세스를 따라가므로 셋 다 없다.

미확인으로 남는 것: qwen 은 프로젝트 로컬 `.qwen/settings.json` 만 확인됐고, codex 는 `CODEX_HOME`
을 갈아끼우면 인증도 같이 갈린다(polycanv 는 `auth.json` 을 심볼릭 링크로 물려줘야 했다).
껍데기가 `-c` 로 넘기면 `CODEX_HOME` 문제는 없지만, codex 의 신뢰 게이트는 남는다(⑧).

**프런트엔드는 브라우저 하나.** 줌이 공짜로 오고, OS 별 패키징이 없다.
(~~`--app=` 으로 창처럼 쓸 수 있다~~ — 2026-09-11 에 뒤집었다. "창 — 2026-09-11" 을 봐라.) TUI 는 만들지 않는다 — polycanv 가 그것이었고, **pane 마다 다른 배율·연속 줌·겹침**이
TUI 에서는 안 됐다. 셋(앱·웹·CLI)을 만들면 기능마다 세 군데를 고쳐야 한다 — 그것이 "무겁다"는
평의 원인이라는 것이 이 프로젝트의 가설이다(평의 출처는 아직 미기록).

**Electron 은 안 쓴다.** 무겁다는 게 이 프로젝트가 피하려는 바로 그것이다 — cate 는 dmg 496MB
(1.7.0), 설치 1.1GB(1.6.0 으로 잰 것)다. 창이 필요하면 Tauri(CodeGrid 가 12.5MB 로 보여 준다).

**`127.0.0.1` 밖으로 열지 않는다.** 이걸 HTTP 로 여는 건 셸을 여는 것이고 인증이 없다.
원격은 `ssh -L` 로 넘긴다. **host 를 바꾸는 옵션 자체를 두지 않는다** — 잊어서가 아니라 뺀 것이다.

(셀이 작아져 터미널마다 행·열이 늘어난다 — 밀도 줌).

뺀 이유는 값이다. 조사로 확인했다: cate 는 카메라 줌 하나를 위해 **여덟 가지를 고쳐야 했다**
(전문은 `own-runtime.md` 의 "줌 아래에서 xterm.js 를 멀쩡하게 두기"). 줌으로 PTY 를 리사이즈하면
90열이 87열이 되고(xterm 이 셀 픽셀을 올림한다), 해상도는 글꼴 크기를 올려 아틀라스를 다시 구워
얻어야 하고, 셀은 축마다 다시 재야 하고, 마우스 좌표는 고쳐 써야 하고, 축소 뒤에는 터미널이
하얘져 강제로 다시 그려야 한다. **cate 는 이걸 여덟 번에 걸쳐 고쳤다** — 견적을 낼 근거는 우리에게 없지만, 한 번에 끝난 적이 없다는 것은 남는다.

나중에 넣을 때의 세 갈래는 조사해 뒀다 — cate 의 계단 배율 + 좌표 고쳐 쓰기, ccanvas 의 정확 추적 +
매번 아틀라스 재굽기, opencove 의 `@xterm/addon-webgl` 패치(`setRasterScale`, 행·열이 구조적으로 안
흔들린다). **넣을지 말지, 어느 길로 갈지는 그때 사람이 정한다.**

**단축키를 화면에 보이게 적는다.** (2026-09-07, 사용자) 카메라 줌을 뺐으니 `Ctrl+-` 가 캔버스를
넓히는 유일한 길인데, **안 보이면 없는 기능이다.** 어디에 어떻게 적을지는 안 정했다 — 빈 캔버스의
안내, 레일 아래 한 줄, 도움말 중 무엇이든 될 수 있다. 다른 단축키도 생기면 같은 자리에 모은다.

**폴더 생성은 넣고, 파일 생성은 안 넣는다.** (2026-09-07, 사용자) 새 프로젝트 폴더를 만들고 거기서
터미널을 여는 것은 런처의 일이다. 파일은 아니다 — 만들면 이름을 고치고 지워야 하고, 그러면 확인
대화상자와 되돌리기가 붙어 파일 관리자가 된다. **그리고 터미널이 바로 거기 있다** — `touch` 가
한 줄이다. 지우기·이름 바꾸기도 같은 이유로 뺀다.

**창 모서리는 둥글다**(macOS 풍). 다만 **빨강·노랑·초록 창 버튼은 쓰지 않는다** — 그 세 색이
정확히 신호등 색이라 사용자가 상태와 헷갈린다. 그 자리(제목 줄 왼쪽 끝)에는 신호등이 앉는다.

**터미널을 닫는 자리는 둘이고, 부수기 전에 제자리에서 한 번 묻는다.** (2026-09-08, #31 ①④)
사용자가 타일과 목록 행 **둘 다**에 손을 뻗었으므로 둘 다에 `×` 를 둔다. 물음은 `window.confirm`
이 아니다 — 그것은 페이지를 통째로 멈춰 `/events` 프레임 처리까지 멈추고, 생김새를 우리가 못 정한다
(이모지로 신호등을 안 그리는 것과 같은 이유). 대신 그 자리에 확인 줄이 펼쳐지고 `Close`·`Cancel`
둘이 `<button>` 이라 **키보드로도 닿는다** — 부수는 것이 마우스로만 닿으면 안 된다.

- **`Close` 는 열릴 때 포커스를 받는다.** 그래야 Tab 없이 키보드로 끝난다. `Esc` 가 그만두기다.
- **그 뒤로는 사용자가 둔 자리를 안 옮긴다.** 목록은 훅·resize 방송마다 통째로 다시 지어지는데,
  다시 지을 때마다 포커스를 `Close` 로 되돌리면 **사용자가 `Cancel` 에 둔 손이 방송 하나에 `Close` 로
  옮겨 가고 같은 Enter 가 그만두기에서 파괴로 바뀐다.** 실측으로 재현했다(2026-09-08 검토, 다른
  세션의 훅 하나에 `Cancel` → `Close`, 그 자리의 Enter 가 `DELETE` 를 냈다). **어느 단추였는지까지
  재서 그 단추로 돌려준다.** `AGENTS.md` 의 "상태만 보고 자동으로 키를 보내지 마라" 와 같은 결이다 —
  방송이 사용자의 손을 옮기면 안 된다.
- **캔버스는 비어 있을 때만 지운다** (2026-09-08, 사용자). 데몬은 처음부터 그 규칙이었고
  (세션이 있으면 409, 마지막 하나여도 409) 화면만 없었다. 화면은 그 두 조건을 **그대로 뒤집어**
  손잡이를 낸다 — 지울 수 있을 때만 × 가 있으므로 거절당할 요청을 낼 일이 없고, 왜 못 지우는지는
  탭 설명이 말한다. **안에 든 셸을 죽이며 지우는 길은 만들지 않는다** — 화면의 동작이 도는
  프로세스를 죽이면 안 된다(원칙 2). 확인은 안 묻는다: 손잡이가 있다는 것이 곧 비어 있다는 뜻이라
  없어지는 것은 이름과 자리뿐이고, 안 위험한 것에까지 확인을 붙이면 정말 위험한 것(터미널 닫기)의
  확인까지 습관으로 넘기게 된다.
- **지우는 길은 `gone` 하나다.** `DELETE` 를 낸 브라우저도 낙관적으로 안 지운다 — 둘째 브라우저와
  같이 움직여야 하기 때문이다(protocol.md "낸 쪽도 방송을 되받는다"). 그래서 **`404` 는 실패가 아니다**:
  남이 먼저 닫은 것이고 사용자가 시킨 결과는 이미 나 있다. 조용히 지나간다.

**git 변경 여부는 안 본다.** 브랜치 이름은 `.git/HEAD` 한 줄이라 공짜지만 `git status` 는 저장소마다
돌려야 해서 비싸다. cate 가 45% CPU 를 냈던 원인이 이런 폴링이었다.

**WSL 은 데몬을 WSL 안에서 돌려 푼다.** 리눅스 프로그램이 리눅스 폴더를 보고 윈도우 브라우저가
접속하는 것뿐이라 공짜다. 윈도우에서 돌면서 WSL 안을 들여다보려 하면 그때 비싸진다.

## 기본 방침 (선례 기반, 아직 안 쟀다)

**줌은 카메라다.** 캔버스 줌 때문에 PTY 크기를 바꾸지 않는다. 창 크기 조절만이 cols/rows 를 바꾼다.
선례는 p1rallels/infinite(실험적, 27★)의 설계 노트와 nodeterm 의 캔버스 좌표계 맞춤이다.
CSS transform 아래 xterm.js 6+WebGL 의 글자 측정은 아직 안 쟀다 — 브라우저 비용 측정에서 같이 본다.

## 보안 — 정해 둔 것 (2026-09-07 감사, #29)

스파이크 코드를 읽고 찾은 것이다. **스파이크는 제품이 아니지만 데몬(#22)이 그 모양을 물려받으므로**
데몬을 짜기 전에 정해 둔다.

**가장 큰 것: 로컬 데몬은 방문한 웹사이트에게 열려 있다.** `127.0.0.1` 에 묶는 것은 보호가 아니다 —
브라우저는 웹소켓에 CORS 를 적용하지 않아서, 아무 탭의 아무 페이지가 `ws://127.0.0.1:8801/pty` 를
열 수 있다. 스파이크 서버는 거기에 **실행할 명령까지 질의 문자열로 받는다.** 둘이 겹치면
방문한 사이트가 사용자 권한으로 명령을 돌린다.

- **클라이언트가 명령을 못 고른다.** 데몬이 `$SHELL` 을 박아 쓴다 — "palmar 는 셸만 연다" 는
  이미 정한 것이라, `cmd` 파라미터를 없애면 이 취약점의 종류 자체가 사라진다.
- **`Origin` 을 검사하고 토큰을 요구한다.** 토큰은 데몬이 뜰 때 만들어 `~/.palmar/run/token`(0600)에
  두고, 페이지가 읽어 보낸다. 파일을 못 읽는 페이지는 못 붙는다.
- **페이지를 받아 가는 데도 자격이 있다 — `?k=` (2026-09-09에 정함).** 토큰이 실리는 요청은
  `GET /` 하나인데 그것이 아무것도 안 묻고 있었다: 같은 기계의 아무 프로세스나 `curl` 한 번으로
  토큰을 받아 진짜 셸을 열었다(실측, #14). 토큰 파일이 0600 이어도 소용없다 — 같은 비밀을 소켓으로
  나눠 주고 있었으니까.
  **열쇠는 `~/.palmar/run/key`(0600)에 남고 뜰 때마다 돌리지 않는다.** 갈림길은 이것 하나였다:

  | | 열쇠를 남긴다 (고른 쪽) | 켤 때마다 새로 |
  |---|---|---|
  | 북마크 | 계속 열린다 | 다시 켤 때마다 깨진다 |
  | 값 | 주소가 브라우저 방문기록에 남는다 | 남는 것이 없다 |

  사용자가 북마크가 사는 쪽을 골랐다(Jupyter 가 하는 방식). 토큰은 그대로 매번 새로 난다 —
  둘은 다른 것이고, 옛 페이지가 "데몬이 다시 떴다" 를 알아채는 길이 토큰 쪽이다.
- **막으려는 상대를 정했다: 같은 기계의 다른 계정 (2026-09-09).** 회사 WSL 처럼 여럿이 붙는 기계를
  상정한다. 이 선이 나머지를 다 정한다 — 아래 두 줄이 그 결과다.
- **판끼리는 격리하지 않는다. 이것은 한계이고, 숨기지 않고 적는다.**
  유닉스 권한은 **사람(UID)을 나누지 프로그램을 나누지 않는다.** `0600` 은 "kmkim 만" 이지
  "palmar 만" 이 아니고, palmar 가 여는 셸도 그 안의 에이전트도 전부 kmkim 이다. 그래서 판 안에서
  도는 것은 `~/.palmar/run/token` 을 읽어 아무 판에나 붙을 수 있고 — 더 크게는 —
  `~/.palmar/bin/claude` 가 판의 PATH **맨 앞**에 있으면서 쓰기 가능하다(실측 확인). 그것을 바꾸면
  이후 모든 판이 그 코드를 돌린다. **판별 토큰으로 좁혀도 이 문은 안 닫힌다.**
  진짜로 막으려면 판마다 다른 UID 나 컨테이너가 필요한데, 그건 palmar 가 다른 물건이 되는 일이다.
  그러니 고치는 척하지 않고 **경계를 정확히 적는다**: 내 권한으로 도는 것은 palmar 를 조종할 수 있다.
  (새 구멍은 아니다 — 그런 것이 있으면 SSH 키도 브라우저 쿠키도 이미 그쪽 것이다. 다만 palmar 는
  그것을 쉽고 구체적으로 만든다. 특히 **다른 에이전트의 승인 프롬프트에 사람 대신 답하기.**)
- **성질은 tmux 와 같지만, 의무는 다르다 (2026-09-09 조사).** 같은 사용자 안에서 판끼리 닿는 것은
  선례가 압도적이다 — tmux FAQ 는 "not security issues", dtach man 은 "파일시스템 검사 말고는 안
  한다", abduco 는 "보안 기능이 아니다" 라고 적어 뒀고, 대부분은 SECURITY.md 조차 없다. 조사 결론:
  **palmar 의 지금 문서가 조사한 어느 도구보다 이 한계를 정확히 적어 뒀다.** 그러니 이것을 취약점이라
  부르지 않는다 — 부르면 남들 전부와 같은 성질을 palmar 만의 결함처럼 만든다.
  **그러나 palmar 는 "이 에이전트가 당신을 기다린다" 를 파는 물건이다.** tmux 는 그런 말을 한 적이
  없다. 승인을 중계하는 화면에는 안 하는 화면에 없는 의무가 하나 생긴다: **사람이 답했는지 모르면
  사람이 답했다고 말하지 않는 것.** 그래서 대기(`waiting`)를 벗어난 판이 **그 판에 브라우저 키 입력이
  없었으면**, 로그와 화면이 "끝남" 이 아니라 **"응답됨 — 여기서 사람이 안 침"** 이라고 적는다.
  palmar 는 자기가 PTY 에 쓴 바이트를 아니까(`send_input` 이 유일한 입력 경로) 이 판별은 정확하다.
  **막는 것이 아니다** — 판은 palmar 밖에서도 조종될 수 있다(옆 판이 토큰을 들거나, shim 을 바꾸거나).
  사고와 선의의 에이전트에는 정확하고, 공격에는 무력하다. 선례는 Claude Code 의 세션 간 메시지가
  같은 접근 모델로 같은 문장을 적어 둔 것이다: "a message from another session never counts as your
  consent." 판끼리 협력하는 기능을 나중에 만들면 그 모양으로 만든다 — 바이트가 아니라 텍스트로,
  출처를 붙여서. **자동 승인은 만들지 않는다**(uzi 가 그것을 기능으로 팔지만, palmar 는 반대다 —
  AGENTS.md "상태만 보고 자동으로 키를 보내지 마라").
- **앱으로 낼 때(#12)는 TCP 포트를 쓰지 않는다 — 유닉스 도메인 소켓/명명 파이프다.**
  열쇠를 훔쳐 가는 길(위)의 뿌리는 포트가 **기계 전체가 공유하는 자원**이라 아무 계정이나 잡을 수
  있다는 것이다. 소켓은 파일이라 파일 권한이 그대로 걸린다 — 0600 이면 다른 계정은 연결 자체가
  안 되고, 훔칠 포트도 없다. 겸해서 화면이 앱 안의 웹뷰라 **주소에 열쇠를 실을 일도 없어져**
  북마크·방문기록·`?k=` 가 통째로 사라진다. 위의 맞바꿈 자체가 없어지는 것이다.
  **브라우저 길은 남는다**(설치 없이 주소만 열면 되는 것이 palmar 의 성격이고, WSL→윈도우가 그
  길이다). 그러니 앱은 더해지는 것이지 대체가 아니고, 브라우저 길에는 포트와 열쇠가 그대로 남는다.
  ①(판 격리)은 앱이 되어도 **그대로다** — 앱도 셸을 내 권한으로 띄우고, Tauri·Electron 은 자식
  프로세스를 샌드박스에 넣지 않는다. 서명된 앱이라는 겉모습이 없는 경계를 있다고 믿게 만들 위험만
  더해진다. (macOS 키체인에 토큰을 두면 파일보다는 낫다 — 서명된 바이너리 단위로 막힌다. 다만
  shim 바꿔치기는 그대로 남는다.)
- **`cwd` 는 뿌리 안으로 제한한다 — 그런데 보기와 열기는 갈렸다 (2026-09-11).** 처음엔 디렉터리
  레일이 뿌리(내 홈 + 내가 소유한 홈들)만 보여 줬는데, 써 보니 `~` 하나만 떠서 답답했다(사용자).
  그래서 **트리는 `/` 부터 어디든 본다** — `GET /api/dirs?path=` 는 `resolve_dir` 로 뿌리 검사 없이
  실제 디렉터리면 연다. 하지만 **터미널을 여는 것은 그대로 뿌리 안**이다 — `POST /api/sessions` 의
  `cwd` 는 `resolve_under_roots` 를 지난다. "어디든 보되, 홈 안에만 연다." 화면은 홈 밖 폴더를 고르면
  열기 단추를 끄고 이유를 적는다. 뿌리 목록은 `/` 를 맨 앞에 얹어 트리 꼭대기를 만들고, 홈에는
  `home` 표시를 달아 브라우저가 경로를 `~` 로 줄일 때 `/` 를 홈으로 착각하지 않게 한다.
  딸린 결과: `list_dirs` 가 자식 메타데이터(브랜치·자식 유무)를 **뿌리 밖에서도 읽는다.** 2026-09-09
  에 뿌리 밖 브랜치가 새는 것을 막았는데, 그 방어는 "뿌리 밖은 못 본다" 에 기댔고 그 전제가 뒤집혔다 —
  `/etc` 를 직접 볼 수 있게 된 이상 그 안의 브랜치를 가리는 것은 방어가 아니라 앞뒤가 안 맞는 것이다.
  데몬을 세우는 함정(`.git/HEAD` FIFO)을 막는 것은 `read_meta` 의 논블로킹이고, 이 결정과 무관하게
  그대로다.
- **`~/.palmar/` 는 0700 이다.** shim 이 PATH 맨 앞에 오므로, 남이 쓸 수 있으면 `claude` 를 칠 때
  무엇이 뜰지 남이 정한다. 핸드오프 소켓·토큰·pane 별 settings 파일을 `/tmp` 에 두지 않는다.
- **pane 식별자는 추측 불가능한 토큰이다.** 순번이면 로컬의 아무 프로세스나 가짜 상태를 보낼 수 있다.
- **`/report` 는 제품에 없다.** 스파이크 계측용이다.

**이미 원칙이던 것:** `127.0.0.1` 밖으로 열지 않고 host 를 바꾸는 옵션도 두지 않는다(원격은 SSH).
훅은 무슨 일이 있어도 0 으로 끝난다.

**안 본 것:** 브라우저 쪽(`app.js`)은 안 봤다 — 이스케이프 시퀀스는 xterm.js 의 몫이고 그 알려진
이슈들은 검토하지 않았다. Tauri 포장·서명·업데이트 채널도 아직이다.

### ① 웹 스택
프레임워크를 쓸 것인가. "가볍게"가 목표이므로 **기본값은 안 쓰는 것**이고, 쓰자고 하려면 이유를
대야 한다. xterm.js 6(DOM 또는 WebGL — canvas 렌더러는 없어졌다)는 어차피 필요하다.
브라우저가 할 일: 웹소켓 → `term.write()` + 흐름 제어 ACK, 드래그·크기 조절 → 리사이즈 메시지,
상태 이벤트 → 색, 창을 앞으로 가져오면 "봤다" 통지, WebGL 컨텍스트 예산.

흐름 제어 단위가 곧 성능이다.

### ② 데몬의 언어 — **정했다: 파이썬** (2026-09-07, 사용자. 되돌릴 수 있게 둔다)

**바닥은 3.9** — `/usr/bin/python3` 이 3.9.6 이고 스파이크 넷이 거기서 다 돈다(스파이크 H).
3.11+ 를 요구하면 `uv` 를 먼저 깔아야 하므로 "설치 0" 이 깨진다.

**잰 것으로 4 대 2 였다.**

| | Python | Bun |
|---|---|---|

흐름 제어가 그것을 지키는 장치다. Bun 쪽은 "덜 좋다" 가 아니라 **우리가 우회할 수 없다** —

반대로 파이썬이 진 둘은 **우리가 메울 수 있다** — 웹소켓은 순수 파이썬 라이브러리로 갈 수 있고,
한 언어는 불편이지 벽이 아니다.

**경쟁자 일곱 중 Bun 을 쓰는 곳은 없다**(다섯이 node-pty, 둘이 Rust). 다만 전부 Electron/Tauri 라
선택지가 달랐고, `Bun.Terminal` 은 2025-12-17 에 나왔다. **근거로는 약하게 본다.**

**되돌릴 수 있게 둔다 — 이게 설계 제약이다.** (사용자: "여차하면 Bun 으로 가자")
나중에 옮기려면 옮길 수 없는 것을 안 만들어야 한다.

- **파이썬에만 있는 것에 기대지 마라.** `send_fds`(핸드오프)는 ⑦ 이 (b) 라 안 쓴다 — 그대로 두면 된다.
  `asyncio` 관용구는 언어에 묶이지만 구조가 아니면 괜찮다.
- **프로토콜을 문서로 고정한다.** 브라우저와 데몬 사이(웹소켓 메시지, 훅 엔드포인트, 재개 오프셋)를
  적어 두면 데몬만 갈아 끼울 수 있다. 지금은 스파이크 코드에만 있다.
- **터미널 상태는 데몬 밖에 둔다.** 화면은 브라우저(xterm.js), 자리는 저장소(③).
  데몬이 들고 있는 것은 fd·링버퍼·훅 짝짓기뿐이어야 한다.
- **파이썬 패키지 생태계에 의존을 늘리지 마라.** 표준 라이브러리로 되는 것은 표준으로 한다.

**뒤집을 조건.** Bun 이 fd 나 pause 를 열어 주고(#41410), 그때까지 파이썬의 웹소켓·성능이

> **이 일에는 이 저장소의 규칙이 그대로 안 걸린다.** AGENTS.md 는 "근거 없이 됐다고 하지 않는다"

> 방식으로 간다 — 잴 수 없는 것을 됐다고 적지 않는 것이 여기서는 더 중요해진다.

> **2026-09-11 에 뒤집었다: ConPTY 를 ctypes 로 직접 짠다.** (사용자: "완벽한게 낫지")

> `dev/win-probe.py`).
>
> **하나 — `pywinpty` 는 palmar 의 바이트를 못 나른다.** `read()` 의 반환형이 `bytes` 가 아니라
> `str` 이다(`winpty/_winpty.pyi` 에서 확인). 즉 PTY 바이트가 UTF-8 디코드를 거친다. 실제로 재 보니:
>
> | 보낸 것 | 받은 것 |
> |---|---|
> | `b'[A' + NUL + b'B]'` | `'[AB]'` — **NUL 이 사라진다** |
> | `b'[' + FF FE + b']'` | `'[\ufffd\ufffd]'` — 잘못된 UTF-8 이 U+FFFD 가 된다 |
> | 한 × 70,000 (210KB) | 한 69,996 + **U+FFFD 8개** |
>
> 8 이라는 숫자가 원인을 말한다 — 210KB ÷ 32KB ≈ 6.4, **읽기 경계마다 한 글자씩** 깨진다.
> palmar 는 바이트 그대로 나르는 관이다(256KB 링버퍼·alt-screen 스캐너·xterm.js 로 가는 길이 전부
> 바이트). **한글을 길게 내는 에이전트가 32KB 마다 한 글자씩 깨지는 터미널**은 이 도구가 아니다.
>

> 것이 나왔다(파이썬 프로세스 2 → 2). 판을 닫을 때마다 에이전트가 살아남는다는 뜻이고, 막으려면
> 판마다 Job Object 가 필요하다 — `CreateJobObjectW` 는 ctypes 로만 닿는다(프로브에서 되는 것도 확인).
> 즉 **pywinpty 를 써도 ctypes 는 들어온다.** 그러면 "830줄을 안 쓰려고" 가 남지 않는다.
>
> 그래서: `palmar/conpty.py` 가 `CreatePseudoConsole` 을 직접 부른다. 의존성은 계속 0 이고, 바이트는
> 바이트로 남는다. 아래 09-09 의 표는 **그때의 판단으로 남겨 둔다** — 무엇을 근거로 골랐고 어느
> 근거가 틀렸는지가 결정보다 오래 남는다.

> ~~2026-09-09 오후에 정한 것: ConPTY 는 직접 안 짠다. `pywinpty` 를 쓴다(윈도우에서만).~~

>
> | | 새 코드 | 의존성 | 잃는 것 |

> 자체가 없다. 어차피 파이썬을 깔아야 하는 곳에서 휠 하나가 더 붙는 것은 지킬 순수함이 없는

> 갈리므로 macOS·리눅스 사용자에게는 **보이지도 않는다**(사용자, 2026-09-09).

>     dependencies = ["pywinpty; sys_platform == 'win32'"]

> **B 를 골라도 여기서 못 재는 것은 그대로다.** 다만 틀릴 수 있는 코드가 830줄에서 300줄로 줄고,
> 그 300줄은 ctypes 배관이 아니라 파이썬 로직이라 남이 읽고 고칠 수 있다.
같은 웹 코드를 **Tauri** 로 감싼다 — Electron 이 아니다. 같은 방식으로 만든 CodeGrid 의 macOS
배포물이 12.5MB 였다(조사). **순서는 브라우저가 먼저다** — 웹으로 만들면 나중에 창으로 감싸는 건
작은 일이고 반대는 아니다.

남은 것은 **언제**다. 앱을 내면 값이 붙는다 — 플랫폼별 빌드와 서명, 자동 업데이트, 그리고
**"설치가 한 줄이어야 한다" 가 "받아서 실행" 으로 바뀐다.** 그 원칙을 앱에도 적용할지, 브라우저
경로에만 남길지도 같이 정한다. (`--app=` 은 크로미엄 계열에만 있다.)

### ⑤ 가벼움의 기준
**"가볍다" 는 크기가 아니라 쓰는 동안 버벅이지 않는 것이다.** (2026-09-07, 사용자가 정정) 배포물
크기도 작으면 좋지만, 재야 할 것은 **자잘한 렉이 없는가** 다. 그러므로 기준은 프레임 시간과
입력 지연으로 잡는다. 넘으면 안 되는 선은 사람이 정한다.

무엇을 재는가 — **전부 부하를 걸어 놓고 잰다.** pane 8개, 그중 하나는 계속 출력 중.

| 무엇 | 재는 법 |
|---|---|
| 창을 끄는 동안 | 드래그하며 프레임 시간(p95, 최악값) |
| 줌하는 동안 | +/- 를 연타하며 같은 값 |
| 키 입력 | 눌러서 화면에 뜰 때까지 |
| 최악 | `yes` 를 틀어 놓고 다른 창에 타이핑 — 막히는가 |
| 유휴 | 아무것도 안 할 때 CPU |

1/N 로 간다는 것(메인테이너 추정), **흐름 제어가 없으면** 출력 많은 pane 하나가 키 입력을 막는다는 것,
**WebGL 컨텍스트가 렌더러당 열여섯 개쯤**이라 넘으면 느린 렌더러로 떨어진다는 것.

**2026-09-07, 스파이크 D 에서 쟀다. 셋 다 문제가 아니었다.**

**그래도 이건 절반이 사람이 봐야 하는 항목이다.** 잰 것은 자동 드래그와 `flood` 셸 루프다.
사람 손, 진짜 에이전트 출력, 통합 GPU 기계는 아직이다. 16ms 가 나와도 미끄러운지는 눈으로 본다.

애니메이션)이 전부 유휴였다. 고치면서 커서 깜박임도 기본 꺼짐으로 돌렸다.

### ⑦ 데몬 재시작 전략 — **정했다: (b) 재시작하지 않는다** (2026-09-07, 사용자)

데몬은 **업데이트 때만** 재시작한다. 그때 에이전트 pane 은 `--resume <id>` 로 다시 띄우고,
**셸 pane 은 죽는다.** herdr·cate 도 콜드 재시작은 이렇게 한다.

**왜 (a) 핸드오프가 아닌가.** 됐는데도 안 골랐다. 스파이크 G 에서 바이트 손실 0, 끊김 27~71ms,
코드 32줄로 성립했다. 그런데 **스파이크 F 가 그 값을 먼저 깎았다** — 에이전트는 SIGWINCH 흔들기로
화면이 되살아나므로, 핸드오프가 지키는 것은 **셸 pane 뿐**이다. 그 하나를 위해 치를 값이 둘이었다.

- **② 가 파이썬으로 굳는다.** fd 전달은 파이썬 표준(`send_fds`)에만 있다 — Bun·Node 는 못 한다.
- **처음부터 그 모양으로 짜야 한다.** 32줄이 싼 이유는 나머지가 이미 그 구조라서다(절대 오프셋 +
  오프셋 재개). 나중에 못 붙인다.

**② 를 열어 두는 값이 더 크다고 봤다.** 아직 제품 코드가 없으니, 나중에 (a) 가 필요해지면 그때
다시 짠다 — 다만 **그 다시 짜기가 공짜가 아니라는 것이 스파이크 G 의 결론**이므로, 이건 값을
알고 미루는 것이지 공짜로 미루는 것이 아니다.

**이 결정이 낳는 것.**
- **② 가 열린 채 남는다** — Python·Bun·Node·Go·Rust 전부 후보다. fd 전달이 더는 기준이 아니다.
- **링버퍼는 여전히 필요하다.** 재접속(⑨) 때 셸 pane 을 되살리는 재료다. 데몬이 죽을 때 넘기지
  않을 뿐이다.
- **업데이트가 파괴적이라는 것을 사용자에게 알려야 한다.** 셸 pane 이 죽는다고 미리 말하고,
  돌고 있는 것이 있으면 물어본다. 이건 화면 항목이다(#28).
- **재시작 없이 오래 도는 것이 전제가 된다.** 데몬이 새는 메모리·fd 가 있으면 (a) 보다 더 아프다.

**뒤집을 조건.** 업데이트가 잦아지거나(주 단위), 셸 pane 에서 긴 작업(빌드·`tail -f`·ssh)을
많이 돌리게 되면 다시 본다. 그때 치를 값은 위의 둘이다.

### ⑧ codex 상태 — **정했다: 타이틀** (2026-09-08)

**훅이 아니라 창 제목이다.** 그리고 그 답은 codex 만의 답이 아니라 **모든 에이전트의 바닥층**이 됐다(#38).

실측(2026-09-08, `pty.fork` 아래에서 각 CLI 를 띄우고 `OSC 0` 을 전부 기록. 계측용 pty 가 기동 시

답을 안 해서 "조용하다" 고 잘못 본 판이 하나 있었다):

그게 필요한 전부였다.

**글자표는 만들지 않는다.** codex 는 점자, Claude Code 는 `◐◑` 다. 표를 만들면 다음 에이전트에서
깨지고, 그러면 훅으로 되돌아간 것과 같다. **제목이 계속 바뀌는 것만** 본다 — 스피너는 정의상 그렇다.
계약은 `protocol.md` "제목으로 읽기" 에 있다.

**`waiting` 을 더 얻는 길도 있다(아직 안 붙였다).** 0.147.0 바이너리에 `[tui].terminal_title` 이 있고
항목 식별자에 **`run-state`** 가 있다. 문자열 `[ ! ] Action Required` 도 있다. 껍데기가
`-c 'tui.terminal_title=["run-state", …]'` 로 넘기면 **설정 파일도, 훅 신뢰 관문도 없이** 정확한

**`--dangerously-bypass-hook-trust` 는 여전히 안 쓴다.** 남의 도구의 보안 결정을 대신 꺼 주는 것이다.
그리고 이제 그럴 이유도 없다 — 제목은 아무 허락도 필요 없다.

### ⑨ 재접속 복원 — **정했다** (2026-09-07)

**에이전트는 SIGWINCH, 셸은 바이트 재생.** 스파이크 F 에서 쟀다 — `claude` 는 크기를 한 칸 바꿨다
되돌리면 전체 화면을 다시 그리고(바이트 하나 재생 안 함), 셸은 alt-screen 이 아니라 흔들어도
프롬프트만 다시 그린다.

**링버퍼는 pane 당 256KB.** (`spikes/2026-09-07/reconnect/RINGSIZE.md`)
실제 출력이 줄당 30~254B(색 있는 `git diff` 가 최악)라, 최악으로 잡아도 1,000줄 = 화면 34개다.
pane 16개면 4MB — 데몬 유휴 25.6MB 위에 얹어도 감당된다.

**alt-screen 에 들어가면 버퍼를 안 키운다.** `ESC[?1049h`/`ESC[?1049l` 을 스트림에서 본다.
들어가기 전 바이트는 남긴다 — 나오면 셸 스크롤백이 이어져야 한다.

**예상이 틀렸던 것도 적어 둔다.** "alt-screen TUI 가 화면을 계속 다시 그려 버퍼를 순식간에 채울
것" 이라고 보고 쟀는데 반대였다 — 진짜 alt-screen `top` 은 초당 1KB 뿐이다(커서로 바뀐 곳만 고친다).
버퍼를 1초에 채우는 것은 alt-screen 이 아니라 **출력량이 많은 아무 프로그램**이다(빌드 로그, `yes`).
그래서 **alt-screen pane 에서 버퍼를 안 키우는 이유는 용량이 아니라 쓸모다.**

**안 정한 것.** 사람이 위로 얼마나 보고 싶어 하는지는 관찰이 아니라 짐작이다 — 256KB 는 "충분해
보이는" 값이다. 쓰다가 부족하면 늘린다. 디스크로 넘기는 길은 지금 안 본다.

**서버에 헤드리스 에뮬레이터를 두는 길(VS Code 방식)은 여전히 아니다** — 흔들기가 되는 이상
pyte 비용을 낼 이유가 없다(polycanv 가 tmux 대비 CPU 8배를 낸 것이 그 비용이다).

### ⑪ 캔버스 여럿 — **정했다: 캔버스 위 탭** (2026-09-08, 사용자)

프로젝트마다 캔버스 하나. **원노트·윈도우 탐색기처럼 캔버스 위에 탭이 붙는다.**

- **탭은 캔버스 위에 있고, 순서를 끌어서 바꿀 수 있다.**
- **탭에는 작은 점 하나만 붙인다** — 그 캔버스에 기다리는 것이 있다는 표시. 그 이상 안 넣는다.
- **왼쪽 터미널 목록은 캔버스와 무관하게 전부 보여 준다.** 상태순은 그대로다 —
  기다리는 것이 어느 캔버스에 있든 맨 위다. 다른 캔버스 것에는 캔버스 이름표가 붙고,
  누르면 그 캔버스로 넘어가며 그 창으로 간다.
- **미니맵은 지금 보고 있는 캔버스 것 하나만** 보여 준다(사용자). 캔버스마다 하나씩 늘어놓지 않는다 —
  전환은 탭이 하고, 미니맵은 "지금 이 캔버스 안에서 내가 어디 있나" 만 답한다.
- **캔버스와 터미널에 이름을 붙일 수 있다**(사용자). 지금은 `shell · ~/work/api` 처럼 경로로만 부른다.

**A(탭)를 반대했던 이유가 사라졌다.** 처음 세 갈래를 그릴 때 A 를 반대한 근거는
"왼쪽 목록이 이 캔버스 것만 보여 주니 다른 캔버스에서 기다리는 것이 점 하나로 줄어든다" 였다.
사용자가 **탭과 전체 목록을 같이** 가져가면서 그 전제가 없어졌다 — **탭은 전환기이고,
안 놓치는 일은 목록이 맡는다.** 둘을 하나로 묶으려 한 것이 내 실수였다.

**같이 정할 것(아직).** 캔버스가 하나뿐일 때 탭 줄을 숨길지. 캔버스 이름을 사람이 짓는지 폴더에서
따는지. 터미널을 다른 캔버스로 옮길 수 있는지. **새 터미널이 지금 캔버스에 뜨는지 그 폴더의
캔버스에 뜨는지** — 마지막 것이 "프로젝트마다 캔버스" 를 자동으로 만들지 손으로 만들지를 가른다.

#### 왼쪽 목록을 캔버스로 묶는다 — 기다리는 것은 그래도 안 숨긴다 (2026-09-08, #31 ③)

**사용자가 매일 쓰면서 요구했다.** "목록은 상태 말고 캔버스로 접혀야 한다"(#31). 위 문단이
목록에 요구한 것은 "캔버스와 무관하게 전부, 상태순" 이었으므로 **이 줄이 그것을 고친다.**

**충돌을 알고 고쳤다.** 목업을 견줄 때 캔버스 우선 묶기를 반대한 근거가 정확히
"접힌 묶음 안에 기다리는 것이 파묻힌다" 였고, **"기다리는 것이 어디 있든 맨 위" 는 palmar 가
존재하는 이유**다. 사용자의 실사용이 목업 논증을 이기지만, 그 근거가 틀렸던 것은 아니다 —
그래서 묶되 보장을 **두 겹**으로 지킨다. (#31 이 준 두 갈래 중 **"접힌 묶음 안에 그대로 남긴다"**
쪽을 골랐다. "기다리는 것을 묶음들 위에 따로 모아 붙인다" 는 안 골랐다 — 아래 "왜 위에 안 모았나".)

1. ~~기다리는 세션이 있는 캔버스 묶음이 목록 맨 위로 뜬다.~~ **되돌렸다(2026-09-08, 사용자).**
   목록의 차례는 이제 **탭 줄과 같다 — 데몬이 준 차례 그대로**고, 무엇이 기다리든 안 움직인다.
   보장을 버린 것이 아니라 **짊어지는 것이 바뀌었다**: 탭의 점, 머리글의 점, 접힌 묶음에도 남는
   기다리는 줄, 그리고 창이 덮였을 때의 알림 — 그때는 없던 넷이 지금은 다 있다. 반면 자리가
   움직이는 값은 계속 나갔다: 손이 가 있는 목록이 눈앞에서 뛰면 훑기가 어렵다.
2. **접힌 묶음도 기다리는 줄은 그대로 그린다.** 접힘이 감추는 것은 나머지뿐이고,
   그 줄에는 `--st-wait` 세로 선이 붙어 "왜 이것만 남았나" 를 말한다.
   감춘 개수는 묶음 아래 `+N more, collapsed` 한 줄로 적고, 머리글의 수는 **언제나 캔버스 전체**다.
   머리글에는 탭과 같은 점(기다리는 것이 있다)이 붙는다 — 새 색은 안 만들었다(⑥ 은 여전히 미정).

둘을 겹쳐야 **접어 둔 채로도 기다리는 줄이 목록 맨 위 근처에 남는다.** 한 겹만으로는 부족하다:
1 만 있으면 접었을 때 사라지고, 2 만 있으면 캔버스 셋째 묶음 안쪽까지 스크롤해야 보인다.

**왜 위에 따로 안 모았나.** 기다리는 줄을 묶음들 **위**로 옮기면 그 줄이 자기 캔버스 묶음에서
빠진다 — 그러면 머리글의 수와 그 아래 줄 수가 어긋나거나, 같은 세션이 두 번 보인다.
**한 세션은 목록에 한 줄이다.** 수가 거짓말을 하면 접힌 묶음을 믿을 수 없고, 접기의 값이 사라진다.

**접힘은 브라우저의 것이다**(`localStorage 'palmar-canvas-groups'`, 캔버스 id 로). 프로토콜에 없다 —
"왼쪽 목록 그룹의 접기·펴기는 그 브라우저의 취향" (protocol.md "없는 것"). 데몬이 다시 뜨면 캔버스
id 가 새로 나므로 저장할 때 지금 없는 id 는 솎는다. **찾는 중에는 접힘을 무시한다** — 안 그러면
맞는 것이 접힌 묶음 안에 숨는다(상태 묶음 때부터의 규칙 그대로).

**캔버스를 하나도 모르는 데몬에서는 옛 상태 묶음 그대로다.** 계약상 캔버스가 0개인 순간은 없으므로
(protocol.md) 그건 "이 데몬은 캔버스를 모른다" 는 뜻이고, 그때 캔버스로 묶을 것이 없다.

**실측(2026-09-08, 헤드리스 크롬 152 + dev-stub).** 접힌 캔버스(세션 3: 기다림 1 · 대기 2)에서
기다리는 줄 하나만 남고(`display: grid`), 머리글 수는 `3`, 아래 줄은 `+2 more, collapsed`,
그 줄이 **목록 전체의 첫 줄**이었다. 새로 고쳐도 접힘과 그 줄이 그대로였다.

**사람이 볼 것.** 1 의 "묶음이 뜬다" 는 목록 차례가 상태에 따라 움직인다는 뜻이다 — 탭 줄은
데몬 차례로 고정이고 목록만 움직인다. 목록은 원래 상태순이었으니 결이 같다고 봤지만,
**"캔버스 자리가 늘 같았으면 좋겠다" 면 이 한 겹을 끄고 2 만 남기면 된다**(그때는 기다리는 줄이
보이기는 해도 맨 위는 아니다).

**보장은 조건이 없다 — 되돌이 길에서도 (2026-09-08 저녁, 검토 뒤).**
위 문단들은 캔버스 묶음만 말했는데, 캔버스를 하나도 모르는 데몬에서 도는 옛 **상태 묶음** 길에는
그 보장이 없었다: 접힌 묶음은 줄을 아예 안 지었고, 거기서 `waiting` 묶음을 접으면 **기다리는 것이
하나도 안 보였다.** 계약상 캔버스가 0개인 순간은 없어(protocol.md: 마지막 하나는 `409`) 지금 데몬으로는
닿지 않는 길이지만, ⑪ 의 문장은 조건 없는 보장이므로 갈아 끼울 데몬(② Bun)에서 잃을 이유가 없다.
**고친 방식: 상태 묶음에서는 `waiting` 묶음을 아예 안 접는다.** 그 묶음은 통째로 기다리는 것이라
"접되 남긴다" 가 성립하지 않는다 — 접으면 곧 다 숨는 것이다. 캐럿을 안 그리고 커서도 손가락이
아니게 두어 **눌러도 아무 일 없는 캐럿**을 만들지 않았다. 머리글은 `<묶음 이름> — always shown`.
실측(2026-09-08, 헤드리스 크롬 152 + `canvases: []` 를 보내는 스텁,
`docs/spikes/2026-09-08/close/f6.py`):
고치기 전 판은 머리글을 누르니 기다리는 줄 1개 → 0개, 고친 뒤는 1개 → 1개.

**접힘이 만든 두 번째 자리 — 확인 줄 (2026-09-08 저녁, 검토 뒤).**
2 는 "접힌 묶음은 `waiting` 인 줄만 그린다" 이므로, **훅 하나가 그 세션을 `waiting` 밖으로 밀면 줄이
조용히 빠진다.** 목록 행의 닫기 확인(#31 ④)은 목록이 통째로 다시 지어져도 살아남으라고 세션 id 를
들고 있는데(`rowConfirm`), 그 id 를 거두는 자리가 없어서 **그 세션이 다시 `waiting` 이 되는 순간
아무도 안 물은 파괴 확인 줄이 되살아났다.** 실측으로 재현했다(f1: 되살아난 `Close` 가
`elementFromPoint` 에 잡히는 자리에 있었다 — `docs/spikes/2026-09-08/close/f1.py`). 하필 그 줄은 사용자가 **답하러 누르러 가는 기다리는
줄**이라 오클릭 하나가 승인을 기다리던 에이전트를 죽인다.
**이번 판에 그 줄이 안 그려졌으면 확인은 끝난 것으로 본다** — 다시 짓기가 끝난 자리에서 거둔다.
접기가 목록에서 줄을 빼는 힘을 가진 이상, 줄에 매달린 상태도 그 힘을 같이 받아야 한다.

### ⑩ 자동 배치 — **정했다: 캔버스는 무한히 자란다** (2026-09-08, 사용자)

**질문 자체가 없어졌다.** "밀 자리가 없을 때 무엇을 하는가" 는 캔버스가 뷰포트에 묶여 있다는
전제 위의 질문이었다. 캔버스가 무한하면 **자리는 항상 있다.**

- **캔버스는 창이 늘어나는 만큼 자란다.** 한계를 두지 않는다.
  **불편은 사용자 몫이다** — 창을 너무 많이 열면 찾기 어려워지는 것은 사용자가 감당한다(사용자 결정).
- **스크롤로 닿는다.** 이건 이미 코드에 있다(`palmar/web/style.css` 의 `.cv-scroll`).
- **미니맵이 지금 보고 있는 자리를 보여 준다.** 새 요구(2026-09-08, 사용자).
- 밀어내기는 그대로 termcanvas 식이다. 밀린 창은 캔버스가 자라며 흡수된다.

**내가 틀렸던 것.** ⑩ 을 세 갈래로 정리하면서 "캔버스 밖으로 밀면 화면 밖을 볼 방법이 없다 —
카메라 줌을 뺐으므로" 라고 적었다. **줌과 스크롤을 같은 것으로 뒀다.** 줌은 *한눈에 여러 개*를
보는 것이고 스크롤은 *하나씩 찾아가는* 것인데, 밀려난 창을 다시 보는 데 필요한 것은 후자다.
그리고 그 스크롤은 이미 구현돼 있었다 — 문서만 보고 정리한 탓이다(사용자가 지적).

**미니맵은 안 무겁다(스파이크 J, `spikes/2026-09-08/minimap/`).**
6000×4000 캔버스에서 8ms마다 스크롤을 왕복시키며 6초씩 쟀다.

| | fps | p95 | 긴 작업 |
|---|---|---|---|
| 미니맵 없음 · pane 16 | 60.0 | 16.7ms | 0 |
| transform · pane 16 | 60.0 | 16.8ms | 0 |
| transform · pane 40 | 60.0 | 16.7ms | 0 |
| 레이아웃 읽기(틀린 길) · pane 40 | 60.0 | 16.7ms | 0 |

미니맵이 있든 없든 프레임 시간이 구분되지 않는다. **`transform` 으로 만든다** — 성능 때문이 아니라
"창마다 값을 내리지 말고 스토어에서 읽어라"(`AGENTS.md`) 때문이다. 위치를 이미 아는데 DOM 에
다시 물어볼 이유가 없다.

**안 잰 것:** 빈 사각형으로 쟀지 진짜 xterm 40개가 아니다. WebGL 없이(헤드리스), 1회, M 계열 맥.
pane 100개 이상은 모른다.

**여전히 정할 것.** 새 창의 기본 크기(cate 640x400 고정 / termcanvas 는 마지막 크기 기억),
밀리는 것을 애니메이션으로 보여 줄지, 되돌리기가 필요한지, 밀어내기 반복 한도(termcanvas 는 20회).
이것들은 만들면서 정해도 되는 것들이다.

### 밀어내기를 만들면서 정한 것 (2026-09-13)

위 넷 중 셋은 만들면서 정해졌고, 하나는 **안 정했다.**

- **애니메이션은 공짜였다.** `.tile` 에 이미 `left`·`top` 트랜지션이 있다(0.35s). 미는 코드는
  좌표만 쓰고, 미끄러지는 것은 CSS 가 한다. 새로 넣은 것이 없다.
- **되돌리기는 있다.** 토스트에 `undo` 를 달았다 — 이건 사실 위에서 이미 정해져 있었다
  ("밀어내기는 토스트로 알린다 — … · undo"). **되돌리는 것은 밀린 창들뿐이고 내가 끈 창은 그대로 둔다.**
  끈 창까지 되돌리면 그건 드래그를 취소하는 것이고, 아무도 그걸 시키지 않았다.
  되돌리면 다시 겹친 상태가 된다 — 그게 "아니, 그냥 둬" 의 뜻이다.
- **반복 한도는 20이다.** termcanvas 의 숫자를 그대로 썼다. **한도에 걸리면 아무것도 안 움직인다** —
  사본 위에서 풀고 다 풀렸을 때만 화면에 쓴다. 절반만 밀린 화면이 제일 나쁘다.
- **새 창의 기본 크기는 안 정했다.** `DEFAULT_W/H` 는 520x360 그대로 잠정이다. 사람이 정할 것.

**언제 미는지도 정해야 했는데, 이건 목록에 없던 것이다.**

- **손을 놓을 때 민다. 끄는 동안은 안 민다.** 끌면서 밀면 지나가는 길에 있는 창이 다 밀려나고
  (거기 놓을 게 아니었는데도), 겨누던 창은 도착하기 전에 도망가 있다. 놓는 순간에 밀면 방금 놓은
  창 밑에서 이웃이 미끄러져 나오고, 토스트가 그걸 그대로 말한다.
- **크기를 키울 때도 민다. 줄일 때는 아무것도 안 당긴다.** 같은 자리(`up()`)를 지난다.
  줄여서 생긴 빈자리를 메우면 그게 타일링이다 — 안 한다.
- **새 창은 아무것도 안 민다.** `firstFree` 가 빈 자리를 찾고, 캔버스가 무한하니 그 찾기는 실패할
  수 없다. 위 결정의 "**새** 터미널이 제자리에 앉고 밀어낸다" 쪽 절반은 **사람이 창을 어디에 겨누는지**가
  화면에 있어야 성립하는데, 캔버스를 눌러서 거기 연다는 것이 아직 없다. **그걸 만들지 말지는 사람이 정할 것.**

### 스위치가 생겼다 (2026-09-14, 사용자)

밀어내기를 실제로 써 본 뒤 **"auto tidy 처럼 옵션으로 on/off 가능하도록"** 이라고 했다.
**이것은 2026-09-07 의 "겹치기 설정을 만들지 마라" 를 뒤집는다** — 끄는 스위치가 곧 그 설정이다.
그때는 밀어내기가 없어서 대안이 "그냥 겹친다" 였고, 지금은 써 보고 정한 것이라 같은 질문이 아니다.

- **자리는 단축키 판**, auto tidy 바로 위. `Push windows aside`.
- **기본은 켜짐.** auto tidy 와 반대다 — auto tidy 는 **안 건드린 창**을 움직이니 기본이 꺼짐이어야
  하지만, 밀어내기가 움직이는 것은 **방금 내 손이 올려놓은 창 밑에 있던 것**뿐이다.
- **`localStorage` 에는 꺼진 상태만 적는다**(`palmar.push = '0'`). 켜짐이 기본이므로 **빈 저장소가
  곧 켜짐**이어야 한다 — 새 프로필이나 저장소를 거부하는 브라우저에서 기능이 조용히 꺼지면 안 된다.
- **끄면 창이 겹친다. 그건 혼란이 아니다** — `focusTile` 이 누른 창을 이미 앞으로 올린다.
- 밀어내기 자체는 한 줄도 안 바뀌었다. `settle()` 맨 위에 가드 하나가 붙었을 뿐이다.

**시험 넷이 지킨다**(`tests/test_browser.py` 의 `PushAside`): 스위치가 있고 켜져서 시작하는가 ·
끄면 **아무것도 안 움직이는가**("덜 움직인다" 가 아니라) · 다시 켜면 다시 미는가 ·
**꺼진 상태만 기록되는가**.

**시험을 쓰면서 두 번 물렸다.** ① `undo` 가 달린 토스트는 **9초**를 떠 있어서 다음 시험이 그걸
자기 것으로 읽는다. ② `put` 으로 창을 옮기면 `.tile` 의 0.35초 트랜지션이 돌아, 곧바로
`getBoundingClientRect()` 를 하면 **중간 위치**를 잡는다 — 앞 시험이 창을 어디 뒀느냐에 따라 드래그
시험이 붙었다 떨어졌다 했다. 둘 다 `setUp` 과 `put` 에 적어 뒀다.

## 창 — 2026-09-11 에 사용자가 말한 것

**WSLg 는 브라우저로 넘기는 통로가 아니라 리눅스 GUI 프로그램 하나다.** (2026-09-11, 사용자:
"wslg는 실행하고 브라우저로 여는게 아니라, obsidian처럼 하나의 linux 프로그램이야") 내가 처음
만든 것은 WSL 을 감지해서 주소를 **윈도우 브라우저**로 넘기는 길이었다. 그건 WSLg 가 아니다.

**남의 브라우저를 빌리지 않는다. 독자 앱이다.** (2026-09-11, 사용자: "chrome 이용하는게아니라
하나의 가벼운 독자적 app을 만들어줘") 그 사이에 Chrome 을 `--app=` 으로 띄우는 길을 만들었다가
지웠다. 창은 떴지만 그건 남의 브라우저이고, 설치 여부·버전·프로필에 매인다.

**그래서 `app/` 이다 — wry + tao, 741KB.** Electron 을 안 쓰는 이유("정한 것" 의 Electron 항목)는
그대로고, 거기 적힌 답이 Tauri 였다. Tauri CLI 와 JS 번들은 뺐다 — **UI 는 이미 데몬이
127.0.0.1 로 내주므로 묶을 프런트엔드가 없다.** 남는 건 창(tao)과 웹뷰(wry) 둘뿐이고, 그 둘이
Tauri 가 그 위에 세워진 것이다. 웹뷰는 OS 가 이미 가진 것을 쓴다(맥 WKWebView, 리눅스·WSLg
WebKitGTK 4.1, 윈도우 WebView2).

**창을 닫아도 데몬은 안 죽는다.** 데몬이 살아 있는 셸을 쥐고 있고 창은 그걸 보는 창일 뿐이다 —
브라우저 탭이 그랬던 것과 같은 규칙이고, ⑦=b(넘겨주기 없음)와 같은 줄에 선다.

**웹도 내고 앱도 낸다 — 고르는 건 쓰는 사람이다.** (2026-09-11, 사용자: "웹버젼도 둘거고,
app버젼도 둘거야" / "웹으로 쓸사람은 웹으로 앱으로 쓸사람은 앱으로 써라 인건데, 동시에 킬 경우도
있겠지?") **한쪽을 접는 문제가 아니다.** 보통은 둘 중 하나만 쓴다. 그래서 `palmar` 는 기본으로
브라우저를 열고(웹 쪽이 한 줄로 끝나게), 창은 `palmar-app` 이 맡는다.

**동시에 켜는 건 흔한 경우가 아니라 "그럴 수도 있는 경우"다 — 그래도 깨지면 안 된다.** 둘은 한
데몬을 보는 두 클라이언트라서, 한쪽에서 연 터미널이 다른 쪽에 그대로 뜬다(실측:
`TwoWaysIn.test_both_open_at_once_see_the_same_workspace`). 한쪽을 닫아도 데몬과 셸은 산다.

**데몬에 `--no-browser` 가 생겼다.** 앱이 데몬을 띄울 때 쓰는 길이고(안 그러면 창과 탭이 둘 다
뜬다), 테스트는 전부 이걸 쓴다 — 안 그러면 테스트마다 브라우저가 열린다.

**둘째 `palmar` 는 거절하지 않고 도는 데몬을 연다.** 둘을 같이 쓰면 "이미 떠 있는데 또 쳤다" 가
사고가 아니라 **평범한 경우**다. 전에는 `exit 1` 로 "`cat run/url` 해 봐라" 했는데, 이제 도는
데몬의 주소를 stdout 마지막 줄에 찍고 브라우저를 열고 0 으로 나간다. **거절이 막고 있던 것은
그대로 막는다** — 토큰을 새로 돌리거나 `run/*.json`(판의 훅 파일)을 지우는 일은 이 길에서
일어나지 않는다(#2). 잠금은 그것들을 건드리기 **전에** 잡으므로 구조적으로 안전하다. 닿지 않는
데몬이 잠금을 쥐고 있는 경우는 여전히 거절이다 — 그건 진짜로 잘못된 상태다.

## 이전 프로젝트에서 배운 것 (되풀이하지 마라)

- **혼자 재면 아무 뜻이 없다.** "40MB" 는 비교 대상이 있어야 크고 작음이 생긴다.
- **벤치마크는 그럴듯한 숫자로 거짓말한다.** `ps` 에 `-p` 를 빼먹어 머신 전체를 합산했고, tmux 를
  전용 소켓 없이 띄워 남의 세션까지 쟀고, 배수 루프에서 잠들어 자기 루프를 쟀다.
  **재는 코드부터 의심해라.**
- **느리지 않은 것을 고치지 마라.** 최적화 전에 어디가 느린지 측정한다.
- **전제가 바뀌면 결론도 다시 적어라.** 근거가 사라졌는데 결론만 남으면 "왜 만들었지?"에 답을 못 한다.
- **엔진을 먼저 받아들이고 요구를 나중에 물었다 — 두 번.** zellij(타일링이라 자유 배치 불가, 설치
  세 줄) 와 herdr(남의 런타임 종속). 요구 — 자유 배치, 설치 한 줄, 종속 없음, UI 보다 오래 사는
  세션 — 를 먼저 적고 엔진을 고른다.

## 이 프로젝트에서 배운 것

- **스키마에 있다고 구현된 게 아니고, 없다고 없는 것도 아니다.** 메서드는 호출해 보고 나서
  "있다"고 적는다. 모르는 필드는 오류 없이 버려진다.
- **소켓 API 만 보지 마라.** herdr 의 답은 `--help` 의 `terminal` 그룹에 있었다. CLI 도 API 다.
- **측정 스크립트가 pane 안에서 죽으면 숫자가 그럴듯하게 작아진다.** 부하를 만든 쪽의 마지막
  줄을 같이 찍어라.
- **대기 루프의 종료 조건에 현재 상태를 넣지 마라.** "이미 done" 을 종료 조건으로 잡아 2ms 에
  빠져나왔다. 기다리는 상태만 종료 조건에 둔다.
- **텍스트와 Enter 를 한 번에 쓰지 마라.** Claude Code 가 제출하지 않는다. 첫 훅 스파이크가
  이걸로 90초 대기를 두 번, 180초를 버렸다.
- **한 번 잰 숫자는 한 번 잰 숫자다.** 표본 수와 측정 창을 숫자 옆에 적어라.
  폴링으로 잰 시각은 그 주기보다 정밀하게 말하지 마라.
- **에이전트 상태를 믿고 자동으로 키를 보내면 사고가 난다.** codex 업데이트 대화상자가 `idle` 로
  보였고, 거기에 보낸 Enter 가 업데이트를 실행했다.
- **테스트 서버·에이전트는 깨끗한 환경에서 띄워라.** 자식이 환경변수를 물려받는다.
- **"아무도 안 만들었다" 는 검색 범위와 함께 적어라.** herdr 위 캔버스는 없었지만 Electron 캔버스는
  여섯 개가 넘었다. 빈자리는 좁게, 정확히 말한다.
- **전임 프로젝트의 기록을 인용할 때는 결론까지 읽어라.** polycanv 가 "글자를 못 줄인다" 로 막힌
  것으로 적었지만, 그 이슈(#20)는 "브라우저가 공짜로 준다" 로 닫혀 있었다.
