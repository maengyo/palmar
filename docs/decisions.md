# 정한 것, 뒤집은 것, 일부러 안 정한 것

## 정한 것 (근거 있음 — 뒤집으려면 근거를 대라)

**런타임은 우리 것이다.** (2026-09-07, 사용자 결정) PTY·세션 유지·상태 수신을 palmer 가 직접
갖는다. 남의 멀티플렉서(herdr·tmux·zellij) 위에 얹지 않는다.
이유는 "기능이 비슷해도 남의 프로그램에 종속되는 것은 별로다" 다.
뒷받침하는 사실은 herdr 스파이크에서 나왔다 — 프로토콜 번호가 0.7.0=14 → 0.8.2=20 으로 오르고
master 는 22 인 것, 스키마에 있는데 구현 안 된 것(`pane_output_changed`, 업스트림은 "계획 없음"),
`pane.wait_for_output` 이 서버 내부 100ms 폴링인 것, 화면 정규식 감지가 codex 대화상자를 놓친 것.
값은 직접 갖는 것의 범위로 낸다: **PTY·바이트·훅·자리, 그 이상은 아니다.**

**터미널 에뮬레이션은 브라우저에서 한다.** polycanv 가 서버(pyte)에서 하다가 부하에서 tmux 의
8배 CPU 를 썼다(polycanv 실측 2026-08-20, `seq 1 200000` 에서 CPU 1.50s vs 0.18s; 벽시계는
1.84s vs 1.14s). xterm.js 가 브라우저에서 하면 서버는 바이트만 옮긴다.
**둘 다 2026-09-07 에 쟀다**(⑤ 와 `own-runtime.md` 스파이크 D) — 서버는 pane 8개 전부 최대
출력에서 CPU 98% · RSS 31MB, 브라우저는 같은 조건에서 60fps 를 지켰다. 재접속 복원을 위해 서버에 헤드리스 에뮬레이터를
두는 것(VS Code 방식)은 같은 비용을 다시 내는 것이라 기본값이 아니다 — ⑨ 에서 다른 길을 먼저 잰다.

**상태는 CLI 의 훅/이벤트로 받는다.** claude·codex·qwen 은 `PermissionRequest`/`Stop` 훅,
opencode 는 SSE. polycanv 가 claude·codex 는 TUI 에서 훅 발화까지 실측했고(2026-08-19),
opencode 는 `/event` 접속까지, qwen 은 `SessionStart` 까지만 확인했다.
이번에 Claude Code 2.1.259 에서 `PermissionRequest` 가 대화상자와 같은 순간에, 승인·질문 구분 없이
오는 것을 다시 실측했다. 화면 정규식은 쓰지 않는다 — herdr 에서 실제로 틀렸다.
(단, codex 의 터미널 타이틀처럼 **CLI 가 상태를 쓰라고 만든 채널**은 정규식이 아니라 이벤트로 본다 — ⑧.)

**세션은 UI 보다 오래 산다.** polycanv #21 이 "이것이 제품이다" 라고 적었다.
그 이슈가 그린 모양은 **직접 데몬을 갖는 것**이었고("a daemon owns the PTYs… the UI becomes a
client that attaches and detaches"), 멀티플렉서에 얹는 길은 거기서 이미 거절됐다("it concedes the
premise that this works without a multiplexer"). herdr 로 간 것은 그 요구가 아니라 "직접 만들면
몇 달" 이라는 2026-09-01 의 견적 때문이었다.
master fd 를 마지막으로 닫는 순간 자식은 SIGHUP 을 받으므로(조사 에이전트의 macOS 로컬 실행,
Linux 는 커널 문서) 누군가 fd 를 들고 있어야 한다. 데몬 재시작 때 fd 를 다음 프로세스에 넘길 수
있다는 것은 실측했다(`docs/own-runtime.md` 스파이크 A) — 무엇을 살릴지는 ⑦ 에서 정한다.

**palmer 는 셸만 연다.** (2026-09-07, 사용자) 폴더를 고르고 버튼을 누르면 그 경로의 셸이 캔버스에
뜨고, 그 안에서 무엇을 돌릴지는 사용자가 정한다. **palmer 는 도구 목록을 갖지 않는다** — claude 를
어떻게 실행하는지 몰라도 된다. polycanv 의 `tools.toml` 이 통째로 사라진다.

**훅은 palmer 가 붙인다 — PATH shim 으로.** (2026-09-07 저녁, 사용자. 같은 날 오전의 "사용자가
한 번 설치한다" 를 뒤집었다) palmer 가 여는 셸의 PATH 맨 앞에 `~/.palmer/bin` 을 둔다. 거기 `claude`
껍데기가 있고, 사용자가 `claude` 를 치면 껍데기가 진짜 `claude --settings /tmp/palmer/<pane>.json` 을
exec 한다. pyenv·rbenv·ccache·Nix `makeWrapper` 가 쓰는 방식이다.

- **사용자는 아무것도 안 한다.** 설치는 한 줄로 돌아온다(원칙 7).
- **사용자 설정 파일을 안 건드린다.** 옛 원칙("사용자의 설정 파일을 고치지 않는다")이 그대로 산다.
- **짝짓기는 URL 에 있다.** settings 파일이 pane 마다 다르고 `?pane=<id>` 가 붙는다. 환경변수도
  `http` 헤더도 필요 없다 — 오전에 "미확인" 이던 그 문제가 사라진다.
- **훅은 무슨 일이 있어도 0 으로 끝난다** — palmer 가 안 떠 있으면 조용히 넘어간다. 이건 그대로.
- **어느 셸이든 된다.** rc 파일을 안 만지니 zsh·bash·fish·WSL 이 같다.

**전제를 실측했다(스파이크 E, `spikes/2026-09-07/shim/`).** `claude --settings X` 는 다른 층의 훅을
**대체하지 않고 병합한다** — 프로젝트 훅과 `--settings` 훅이 `SessionStart`·`UserPromptSubmit`·`Stop`
세 이벤트 모두에서 둘 다 발화했다(Claude Code 2.1.263, 1회). `http` 훅 타입도 실제로 받았다 —
`UserPromptSubmit`·`Stop` 은 왔고 **`SessionStart` 는 안 왔다**(command 타입은 왔다). 1회 관측이라
재확인 대상이지만, 상태에 쓰는 세 이벤트에는 걸리지 않는다.

**비켜 가는 경우.** `command claude`·절대 경로·`npx` 로 껍데기를 우회하거나, palmer 밖에서 띄운
`claude` 는 훅이 없다. 그때 palmer 는 **회색 = 모름** 으로 두고 알려 준다(⑥). 이 경우의 대안으로
OpenCove 가 쓰는 **세션 파일 감지**(에이전트가 디스크에 남기는 기록을 읽는다)를 #20 에서 같이 본다.

**codex 는 껍데기가 `-c` 로 설정을 넘기거나 터미널 타이틀을 읽는다** — PTY 를 palmer 가 소유하니
타이틀 변경은 이미 우리 손에 온다(⑧ 에서 정한다). **opencode 는 설치할 것이 없다.**

프로젝트마다 파일을 심는 길(cate 방식, `.claude/settings.local.json`)은 여전히 아니다 — 터미널이
여러 프로젝트에 흩어지고, `cd` 하면 벗어나고, codex 신뢰가 해시 단위라 프로젝트마다 다시 승인이다.
껍데기는 프로세스를 따라가므로 셋 다 없다.

미확인으로 남는 것: qwen 은 프로젝트 로컬 `.qwen/settings.json` 만 확인됐고, codex 는 `CODEX_HOME`
을 갈아끼우면 인증도 같이 갈린다(polycanv 는 `auth.json` 을 심볼릭 링크로 물려줘야 했다).
껍데기가 `-c` 로 넘기면 `CODEX_HOME` 문제는 없지만, codex 의 신뢰 게이트는 남는다(⑧).

**프런트엔드는 브라우저 하나.** 줌이 공짜로 오고, OS 별 패키징이 없고, `--app=` 으로 창처럼
쓸 수 있다. TUI 는 만들지 않는다 — polycanv 가 그것이었고, **pane 마다 다른 배율·연속 줌·겹침**이
TUI 에서는 안 됐다. 셋(앱·웹·CLI)을 만들면 기능마다 세 군데를 고쳐야 한다 — 그것이 "무겁다"는
평의 원인이라는 것이 이 프로젝트의 가설이다(평의 출처는 아직 미기록).

**Electron 은 안 쓴다.** 무겁다는 게 이 프로젝트가 피하려는 바로 그것이다 — cate 는 dmg 496MB
(1.7.0), 설치 1.1GB(1.6.0 으로 잰 것)다. 창이 필요하면 Tauri(CodeGrid 가 12.5MB 로 보여 준다).

**`127.0.0.1` 밖으로 열지 않는다.** 이걸 HTTP 로 여는 건 셸을 여는 것이고 인증이 없다.
원격은 `ssh -L` 로 넘긴다. **host 를 바꾸는 옵션 자체를 두지 않는다** — 잊어서가 아니라 뺀 것이다.

## 화면 — 2026-09-07 에 사용자가 말한 것

스케치로 확인했다. 그림은 대화의 아티팩트에 있고, 여기가 정본이다.

**캔버스 양옆에 레일이 있다.**
- **오른쪽: 디렉터리.** 폴더만 보이고 파일은 안 보인다 — 파일 트리가 아니라 런처다.
  폴더를 고르고 버튼을 누르면 그 경로의 셸이 캔버스에 뜬다.
  **권한이 닿는 홈이 다 보인다**(`/Users`·`/home` 을 한 번 읽는다). git 저장소는 브랜치가 옆에 붙는다.
  **펼칠 때만 그 폴더 하나를 읽는다** — 홈 전체를 훑지 않고, 트리를 지켜보지도 않는다.
  대신 **새로고침 버튼**이 있다.
- **왼쪽: 터미널 목록.** 상태별로 묶고 기다리는 것이 맨 위에 온다. 창이 밀려 자리를 옮겼거나
  화면 밖에 있어도 여기서는 보인다 — **이게 밀어내기를 해도 되는 이유다.** 창은 움직여도
  목록의 자리는 안 움직인다. 누르면 그 창으로 간다.
  아래에 어느 에이전트에 훅이 깔렸는지 보인다.
- **좌우는 2026-09-07 에 뒤집었다**(사용자). 처음엔 파일 탐색기 관례를 따라 디렉터리를 왼쪽에
  뒀는데, 늘 보는 것은 목록이고 디렉터리는 가끔 쓰는 런처라 자리를 바꿨다.

**겹치지 않는다. 새 창이 옆을 민다.** (2026-09-07, 사용자) 새 터미널은 빈 자리를 찾지 않고
**제자리에 앉고, 거기 있던 창을 밀어낸다** — termcanvas 방식이다. 겹친 만큼만 최단 거리로 밀고,
밀린 창이 또 겹치면 이어서 민다. **겹치기 설정은 없앴다** — 겹칠 일이 없으니 켤 것도 끌 것도 없다.
크기는 사용자가 정하고 palmer 가 푸는 것은 겹침뿐이다(타일링이 아니다).
**밀 자리가 없을 때 어떻게 하는지는 아직 안 정했다(⑩).**

**하나를 캔버스 크기로 펴서 본다.** (2026-09-07, 사용자) 제목 줄의 확대 버튼을 누르면 그 터미널이
캔버스를 다 쓴다. **행·열이 실제로 늘어난다** — 카메라 줌이 아니라 진짜 리사이즈라, 원칙("창 크기
조절만이 행·열을 바꾼다")과 어긋나지 않는다. `Esc` 로 돌아오면 나머지는 있던 자리에 그대로 있다.
**레일은 남는다** — 크게 보는 동안에도 누가 기다리는지는 보여야 하기 때문이다.
카메라 줌을 뺀 자리를 이것이 메운다: 멀리서 다 보는 대신 하나를 가까이 본다.

**디자인은 OpenCove·Collaborator 수준을 목표로 한다.** (2026-09-07, 사용자) 둘의 화면을 직접 보고
공통점을 가져왔다. 정본 화면은 대화의 아티팩트("palmer")에 있고, 결정은 여기 적는다.

- **테마 둘.** 밝은 쪽은 **종이**(바닥 `#f3f1ec`, 타일 `#fcfbf8` — 순백이 아니다, 대비가 세서 눈이
  피로하다). 어두운 쪽은 **푸른 유리**(타일 `#050608` 검정, 캔버스는 `rgba(22,31,54,.78)` 반투명
  파랑 — 뒤 그라디언트가 비친다). 기본은 OS 를 따르고, 상단 바 버튼으로 고정한다.
- **타일은 캔버스와 반대 방향으로 한 단계.** 어두운 테마에선 캔버스보다 더 검고, 밝은 테마에선 더 밝다.
  그림자 카드가 아니라 **가는 선 하나**로 경계를 낸다(Collaborator).
- **글꼴은 모노스페이스 하나.** JetBrains Mono. 산세리프 없음. 터미널 도구라는 것이 글꼴에서 보인다.
- **UI 글자는 영어.** 두 참고 제품이 그렇고 README 도 영어다. 한글 UI 로 바꾸려면 한글 모노 글꼴이
  필요해 글꼴 선택이 달라진다 — 사용자가 첫 디자인을 "좋아" 로 받았으니 영어로 간다.
- **신호등은 테마마다 따로.** 어두운 호박 `#e2a63a` 를 종이에 올리면 대비 2:1 로 글자로 못 읽는다.
  밝은 쪽은 한 단계 진하게(`#a8730f` 등). 색은 테마가 바뀌어도 상태 전용이다.
- **세션 목록 항목** = 점 · 이름 · 경로 · 경과 시간 · **마지막 한 줄**(OpenCove). 기다리는 항목의
  한 줄은 호박색으로 — "Do you want to proceed? · ls /usr/bin | wc -l".
- **캔버스 밖 세션에는 `↗ off` 배지.** 목록이 있어야 밀어내기가 성립한다는 걸 화면이 스스로 말한다.
- **타일 제목 줄** = 점 · 이름 · 경로 · 상태 알약(`waiting`/`working`/`done`) · 행×열 · 확대 네모.
  확대 아이콘은 글꼴에 기대지 않고 CSS 로 그린 네모다.
- **밀어내기는 토스트로 알린다** — "Opened zsh in ~/work/api · moved 1 window · undo".
  움직임은 애니메이션이라 정지 화면엔 없다.
- **없는 것**: 캔버스 +/- 버튼, 미니맵(목록이 그 역할), 타일의 빨강·노랑·초록 버튼, 드래그 없는
  목업의 겹침(충돌 처리 없는 드래그는 거짓말이라 목업에서 뺐다).
- **상태 바**에 `daemon 127.0.0.1:8801 · 7 sessions · 25.6 MB` — 잰 숫자를 화면에 둔다.

**아직 안 그린 화면**: 첫 실행(빈 캔버스), 훅 설치 안내, 설정, 세션 스무 개일 때의 목록.
앞의 둘은 원칙 7(설치 한 줄)과 "훅이 없는 것을 스스로 알아챈다" 에 걸려 있어 제품 결정이 붙는다.

**카메라 줌은 첫 버전에서 뺀다.** (2026-09-07, 사용자) 캔버스에 +/- 버튼을 두는 대신
**브라우저의 `Ctrl+-` 를 화면에 잘 보이게 적는다.** 그게 이미 캔버스를 더 보여 주기 때문이다
(셀이 작아져 터미널마다 행·열이 늘어난다 — 밀도 줌).

뺀 이유는 값이다. 조사로 확인했다: cate 는 카메라 줌 하나를 위해 **여덟 가지를 고쳐야 했다**
(전문은 `own-runtime.md` 의 "줌 아래에서 xterm.js 를 멀쩡하게 두기"). 줌으로 PTY 를 리사이즈하면
90열이 87열이 되고(xterm 이 셀 픽셀을 올림한다), 해상도는 글꼴 크기를 올려 아틀라스를 다시 구워
얻어야 하고, 셀은 축마다 다시 재야 하고, 마우스 좌표는 고쳐 써야 하고, 축소 뒤에는 터미널이
하얘져 강제로 다시 그려야 한다. **cate 는 이걸 여덟 번에 걸쳐 고쳤다** — 견적을 낼 근거는 우리에게 없지만, 한 번에 끝난 적이 없다는 것은 남는다.

나중에 넣을 때의 세 갈래는 조사해 뒀다 — cate 의 계단 배율 + 좌표 고쳐 쓰기, ccanvas 의 정확 추적 +
매번 아틀라스 재굽기, opencove 의 `@xterm/addon-webgl` 패치(`setRasterScale`, 행·열이 구조적으로 안
흔들린다). **넣을지 말지, 어느 길로 갈지는 그때 사람이 정한다.**

**단축키를 화면에 보이게 적는다.** (2026-09-07, 사용자) 카메라 줌을 뺐으니 `Ctrl+-` 가 캔버스를
넓히는 유일한 길인데, **안 보이면 없는 기능이다.** 어디에 어떻게 적을지는 안 정했다 — 빈 캔버스의
안내, 레일 아래 한 줄, 도움말 중 무엇이든 될 수 있다. 다른 단축키도 생기면 같은 자리에 모은다.

**폴더 생성은 넣고, 파일 생성은 안 넣는다.** (2026-09-07, 사용자) 새 프로젝트 폴더를 만들고 거기서
터미널을 여는 것은 런처의 일이다. 파일은 아니다 — 만들면 이름을 고치고 지워야 하고, 그러면 확인
대화상자와 되돌리기가 붙어 파일 관리자가 된다. **그리고 터미널이 바로 거기 있다** — `touch` 가
한 줄이다. 지우기·이름 바꾸기도 같은 이유로 뺀다.

**창 모서리는 둥글다**(macOS 풍). 다만 **빨강·노랑·초록 창 버튼은 쓰지 않는다** — 그 세 색이
정확히 신호등 색이라 사용자가 상태와 헷갈린다. 그 자리(제목 줄 왼쪽 끝)에는 신호등이 앉는다.

**git 변경 여부는 안 본다.** 브랜치 이름은 `.git/HEAD` 한 줄이라 공짜지만 `git status` 는 저장소마다
돌려야 해서 비싸다. cate 가 45% CPU 를 냈던 원인이 이런 폴링이었다.

**WSL 은 데몬을 WSL 안에서 돌려 푼다.** 리눅스 프로그램이 리눅스 폴더를 보고 윈도우 브라우저가
접속하는 것뿐이라 공짜다. 윈도우에서 돌면서 WSL 안을 들여다보려 하면 그때 비싸진다.

## 보안 — 정해 둔 것 (2026-09-07 감사, #29)

스파이크 코드를 읽고 찾은 것이다. **스파이크는 제품이 아니지만 데몬(#22)이 그 모양을 물려받으므로**
데몬을 짜기 전에 정해 둔다.

**가장 큰 것: 로컬 데몬은 방문한 웹사이트에게 열려 있다.** `127.0.0.1` 에 묶는 것은 보호가 아니다 —
브라우저는 웹소켓에 CORS 를 적용하지 않아서, 아무 탭의 아무 페이지가 `ws://127.0.0.1:8801/pty` 를
열 수 있다. 스파이크 서버는 거기에 **실행할 명령까지 질의 문자열로 받는다.** 둘이 겹치면
방문한 사이트가 사용자 권한으로 명령을 돌린다.

- **클라이언트가 명령을 못 고른다.** 데몬이 `$SHELL` 을 박아 쓴다 — "palmer 는 셸만 연다" 는
  이미 정한 것이라, `cmd` 파라미터를 없애면 이 취약점의 종류 자체가 사라진다.
- **`Origin` 을 검사하고 토큰을 요구한다.** 토큰은 데몬이 뜰 때 만들어 `~/.palmer/run/token`(0600)에
  두고, 페이지가 읽어 보낸다. 파일을 못 읽는 페이지는 못 붙는다.
- **`cwd` 는 디렉터리 레일이 보여 주기로 한 뿌리 안으로 제한한다.**
- **`~/.palmer/` 는 0700 이다.** shim 이 PATH 맨 앞에 오므로, 남이 쓸 수 있으면 `claude` 를 칠 때
  무엇이 뜰지 남이 정한다. 핸드오프 소켓·토큰·pane 별 settings 파일을 `/tmp` 에 두지 않는다.
- **pane 식별자는 추측 불가능한 토큰이다.** 순번이면 로컬의 아무 프로세스나 가짜 상태를 보낼 수 있다.
- **`/report` 는 제품에 없다.** 스파이크 계측용이다.

**이미 원칙이던 것:** `127.0.0.1` 밖으로 열지 않고 host 를 바꾸는 옵션도 두지 않는다(원격은 SSH).
훅은 무슨 일이 있어도 0 으로 끝난다.

**안 본 것:** 브라우저 쪽(`app.js`)은 안 봤다 — 이스케이프 시퀀스는 xterm.js 의 몫이고 그 알려진
이슈들은 검토하지 않았다. Tauri 포장·서명·업데이트 채널도 아직이다.

## 안 정한 것 (스파이크 뒤에 사람이 정한다)

### ① 웹 스택
프레임워크를 쓸 것인가. "가볍게"가 목표이므로 **기본값은 안 쓰는 것**이고, 쓰자고 하려면 이유를
대야 한다. xterm.js 6(DOM 또는 WebGL — canvas 렌더러는 없어졌다)는 어차피 필요하다.
브라우저가 할 일: 웹소켓 → `term.write()` + 흐름 제어 ACK, 드래그·크기 조절 → 리사이즈 메시지,
상태 이벤트 → 색, 창을 앞으로 가져오면 "봤다" 통지, WebGL 컨텍스트 예산.
**웹소켓 연결을 pane 마다 둘지 하나로 다중화할지도 여기서 정한다** — pane 8~16개면 연결 수와
흐름 제어 단위가 곧 성능이다.

### ② 데몬의 언어
먼저 잴 둘은 이렇다(조사, `docs/own-runtime.md` 표).
- **Python**: PTY·크기·**fd 전달**이 전부 표준 라이브러리. 웹소켓 서버만 표준에 없다(순수 파이썬
  패키지 하나, 또는 손으로 짠 RFC 6455). 단일 스레드여야 한다(`pty.fork` + 스레드 금지).
  설치: macOS 의 `/usr/bin/python3` 은 Xcode CLT 설치를 권하는 스텁이고 CLT 를 깔면 3.9.6 이라,
  3.11+ 를 요구하면 `uv` 를 먼저 깔아야 한다. **바닥을 3.9 로 잡는 길도 있다** — `pty.fork`·
  `fcntl.ioctl(TIOCSWINSZ)`·`socket.send_fds` 는 전부 3.9 에 있고 잃는 것은 편의 함수뿐이다(조사).
  polycanv 코드(상태 계약·훅·브리지·PTY)를 그대로 가져온다.
- **Bun**: **내장 PTY(`Bun.Terminal`)와 내장 웹소켓 서버**. 프런트와 한 언어. 63MB 단일 바이너리를
  설치 스크립트로 깔고 `bunx`. **fd 전달은 못 한다** → ⑦ 에서 핸드오프를 고르면 탈락한다.
  인라인 `terminal:` 만 써야 하는 버그, Linux `exit` 콜백 이슈가 있다.
  이미 Node 를 가진 사용자에게도 Bun 은 새 설치다(63MB) — 그 값은 ② 의 설치 측정에서 잰다.
- **Node**: 내장 PTY 가 없고 node-pty 는 네이티브 애드온이다. 툴체인 없이 macOS+Linux 를 덮으려면
  1.2.0-beta.15 고정이 필요하다(안정판 1.1.0 은 mac 프리빌트의 실행 비트가 빠져 깨졌고 Linux
  프리빌트가 없다; 안정판 요청 #919 열림). fd 전달도 못 한다.
  **먼저 재는 둘에는 넣지 않되, 후보에서 빼는 것은 사람이 정한다.**
- **Go/Rust**: 사용자에겐 깨끗하지만 컴파일 언어 채택과 릴리스 파이프라인 비용이 든다. fd 전달은
  될 것으로 보지만 이번 조사에 없다 — 쓰려면 따로 확인한다.

**정하는 방법:** PTY → 웹소켓 → xterm.js 파이프라인을 Python 과 Bun 으로 각각 만들어 지연·CPU·최대
출력·pane 8개·설치 한 줄을 같은 조건에서 잰다. 그 숫자와 ⑦ 의 선택을 놓고 사람이 정한다.
**둘로 시작하는 것도 사람이 바꿀 수 있다** — Node·Go·Rust 를 재라고 하면 같은 조건으로 더 만든다.
무엇을 재느냐가 이미 후보를 고르는 일이기 때문이다.

**2026-09-07 에 쟀다(스파이크 D). 속도로는 안 갈렸다.** pane 8개 전부 최대 출력에서 Python 98% ·
34MB/s, Bun 97% · 34MB/s 로 사실상 같다. 병목이 언어가 아니라 같은 일(PTY 읽기·웹소켓 프레임·
소켓 쓰기)이기 때문이다. **갈린 것은 둘이다.**

| | Python | Bun |
|---|---|---|
| ACK 를 끊었을 때 | **0% CPU — PTY 읽기를 진짜 멈춘다** | 97% CPU — 계속 보낸다 |
| pane 8 전부 출력 시 RSS | 31MB | 87MB |

Bun 은 `Bun.Terminal` 에 pause 가 없어 브라우저가 느려도 못 멈춘다(이슈 #41410 이 실물로 확인됐다).
우회하려면 자식에게 SIGSTOP 을 보내야 한다.

**2026-09-07 저녁, ⑦ 이 (b) 로 정해지면서 fd 전달은 기준에서 빠졌다.** 핸드오프를 안 하므로
Bun·Node 가 그것 때문에 탈락하지는 않는다. **남은 차이는 흐름 제어 하나다** — 브라우저가 느릴 때
파이썬은 PTY 읽기를 진짜 멈추고(0% CPU) Bun 은 못 멈춘다(97%, RSS 31MB 대 87MB). 그래도 ② 는 사람이 정한다 — 설치 한 줄(원칙 7)은 아직 안 쟀고,
프런트와 한 언어라는 값은 숫자에 안 나온다.

### ③ 좌표·크기·배치를 어디에 두는가
palmer 가 보관하는 것은 정해졌다. 로컬 파일(데몬 쪽)인가, 브라우저 저장소인가. 데몬이 UI 보다 오래
사는 설계라면 데몬 쪽이 자연스럽지만, 아직 정하지 않는다.

### ④ 앱은 언제 내는가
**방향은 정해졌다**(2026-09-07, 사용자): 옵시디언처럼 macOS·Windows·Linux AppImage·deb 를 낸다.
같은 웹 코드를 **Tauri** 로 감싼다 — Electron 이 아니다. 같은 방식으로 만든 CodeGrid 의 macOS
배포물이 12.5MB 였다(조사). **순서는 브라우저가 먼저다** — 웹으로 만들면 나중에 창으로 감싸는 건
작은 일이고 반대는 아니다.

남은 것은 **언제**다. 앱을 내면 값이 붙는다 — 플랫폼별 빌드와 서명, 자동 업데이트, 그리고
**"설치가 한 줄이어야 한다" 가 "받아서 실행" 으로 바뀐다.** 그 원칙을 앱에도 적용할지, 브라우저
경로에만 남길지도 같이 정한다. (`--app=` 은 크로미엄 계열에만 있다.)

### ⑤ 가벼움의 기준
**"가볍다" 는 크기가 아니라 쓰는 동안 버벅이지 않는 것이다.** (2026-09-07, 사용자가 정정) 배포물

| pane 8, DOM 렌더러 | 60 | 18.4ms | 18.7ms | 0 | 5.4ms |

\* 그 줄은 계측하는 pane 자신도 출력 중이라 부분 문자열 판정이 아무 글자에나 걸린다. 버린다.
그리고 **"키→에코" 는 화면에 그려진 시각이 아니다** — 바이트가 브라우저에 도착한 시각이다.
페인트까지는 한 프레임(≤17ms)이 더 든다.

**흐름 제어를 넣으면 파서 문제와 키 막힘이 크게 준다** — 대체로 ACK 한 만큼 오므로 브라우저가
속도를 정한다. 다만 엄격한 크레딧은 아니다: 한도를 5ms 치 + 한 번의 읽기 예산(256KB)만큼
넘길 수 있다(`pipeline/README.md` 의 "정확히 재지 않는 것"). WebGL 은 한 탭에서 16개가 다
승인됐다. 서버(파이썬)는 같은 조건에서 CPU 98% · RSS 31MB. 자세한 건 `own-runtime.md` 스파이크 D.

**그래도 이건 절반이 사람이 봐야 하는 항목이다.** 잰 것은 자동 드래그와 `flood` 셸 루프다.
사람 손, 진짜 에이전트 출력, 통합 GPU 기계는 아직이다. 16ms 가 나와도 미끄러운지는 눈으로 본다.

**비교 대상:** 셸만 · tmux · polycanv(55MB/1개, 75MB/8개, 부하 CPU tmux 의 8배) · herdr 서버
(35MB + 6MB/pane — 1회 측정, 기준선으로 쓰기 전에 다시 잰다) · cate(dmg 496MB/1.7.0, 설치 1.1GB/1.6.0,
메모리 미공개) · Electron 캔버스들(dmg 153~168MB) · Horizon(Rust, tar.gz 23MB) · CodeGrid(Tauri, 12.5MB).
polycanv 의 `scripts/dev/bench.py` 를 가져와 palmer 열을 추가한다.
**유휴 비용도 본다** — cate 가 45% 를 냈던 원인(1초 lsof/프로세스 폴링, blur 위에 항상 켜진 CSS
애니메이션)이 전부 유휴였다. 고치면서 커서 깜박임도 기본 꺼짐으로 돌렸다.

### ⑥ 신호등 색 매핑
AGENTS.md 는 색을 상태의 것으로 예약만 해 둔다. polycanv 는 초록=일하는 중, 호박=기다림,
빨강=끝남, 회색=대기 였다. palmer 의 매핑과 "에이전트 없음"·"모름"·"오류(`StopFailure`)" 의
표현은 사람이 정한다. 정해질 때까지 초록·호박·빨강·회색을 다른 데 쓰지 않는다.

### ⑦ 데몬 재시작 전략 — **정했다: (b) 재시작하지 않는다** (2026-09-07, 사용자)

데몬은 **업데이트 때만** 재시작한다. 그때 에이전트 pane 은 `--resume <id>` 로 다시 띄우고,
**셸 pane 은 죽는다.** herdr·cate 도 콜드 재시작은 이렇게 한다.

**왜 (a) 핸드오프가 아닌가.** 됐는데도 안 골랐다. 스파이크 G 에서 바이트 손실 0, 끊김 27~71ms,
코드 32줄로 성립했다. 그런데 **스파이크 F 가 그 값을 먼저 깎았다** — 에이전트는 SIGWINCH 흔들기로
화면이 되살아나므로, 핸드오프가 지키는 것은 **셸 pane 뿐**이다. 그 하나를 위해 치를 값이 둘이었다.

- **② 가 파이썬으로 굳는다.** fd 전달은 파이썬 표준(`send_fds`)에만 있다 — Bun·Node 는 못 한다.
- **처음부터 그 모양으로 짜야 한다.** 32줄이 싼 이유는 나머지가 이미 그 구조라서다(절대 오프셋 +
  오프셋 재개). 나중에 못 붙인다.

**② 를 열어 두는 값이 더 크다고 봤다.** 아직 제품 코드가 없으니, 나중에 (a) 가 필요해지면 그때
다시 짠다 — 다만 **그 다시 짜기가 공짜가 아니라는 것이 스파이크 G 의 결론**이므로, 이건 값을
알고 미루는 것이지 공짜로 미루는 것이 아니다.

**이 결정이 낳는 것.**
- **② 가 열린 채 남는다** — Python·Bun·Node·Go·Rust 전부 후보다. fd 전달이 더는 기준이 아니다.
- **링버퍼는 여전히 필요하다.** 재접속(⑨) 때 셸 pane 을 되살리는 재료다. 데몬이 죽을 때 넘기지
  않을 뿐이다.
- **업데이트가 파괴적이라는 것을 사용자에게 알려야 한다.** 셸 pane 이 죽는다고 미리 말하고,
  돌고 있는 것이 있으면 물어본다. 이건 화면 항목이다(#28).
- **재시작 없이 오래 도는 것이 전제가 된다.** 데몬이 새는 메모리·fd 가 있으면 (a) 보다 더 아프다.

**뒤집을 조건.** 업데이트가 잦아지거나(주 단위), 셸 pane 에서 긴 작업(빌드·`tail -f`·ssh)을
많이 돌리게 되면 다시 본다. 그때 치를 값은 위의 둘이다.

### ⑧ codex 상태 — 훅 vs 타이틀
codex 는 신뢰되지 않은 훅을 실행하지 않는다 — 공식 문서는 기동 시 경고를 찍는다고 하고(조사),
TUI 는 디렉터리·훅 두 단계 신뢰 프롬프트를 띄운다(polycanv TUI 실측). polycanv 가 `codex exec` 에서
본 "조용한 미발화" 는 비대화형 경로였다. `--dangerously-bypass-hook-trust` 는 사용자의 보안
결정을 대신하는 것이라 polycanv 는 쓰지 않기로 했다. 두 길: (a) "한 번 신뢰시키면 영속" 을
안내한다, (b) codex TUI 의 터미널 타이틀(`tui.terminal_title` 에 `status` 를 넣으면 `Working`/
`Action Required`)을 xterm.js 의 타이틀 이벤트로 읽는다 — 훅도 신뢰도 필요 없다(조사, 소스 기준,
0.147.0 실물 미확인). 그리고 codex 는 기동 시 업데이트 대화상자를 띄울 수 있다 — 그 위에 아무것도
자동으로 보내지 않는다.

### ⑨ 재접속 복원
**절반이 답이 나왔다(2026-09-07, 스파이크 F).**

- **에이전트(alt-screen)는 SIGWINCH 흔들기로 된다.** `claude` 는 크기를 한 칸 바꿨다 되돌리면
  전체 화면을 다시 그린다 — 배너·대화·대화상자·입력줄까지 바이트 하나 재생하지 않고 돌아왔다.
  화면을 넘치는 출력에서도 보이는 부분이 정확히 같았다.
- **셸은 안 된다.** alt-screen 이 아니라 흔들어도 프롬프트만 다시 그린다. **원시 바이트 재생**이
  답이고, 그래서 링버퍼가 필요하다. 다만 alt-screen 앱보다 싸다 — 셸은 다시 그리지 않으므로
  재생이 곧 화면이다.

**⑦ 이 (b) 로 정해져 좁혀졌다(2026-09-07).** 링버퍼는 **재접속용으로만** 있으면 된다 —
데몬이 죽을 때 넘길 일이 없으므로 크기가 프로세스 메모리에만 걸린다.

**정할 것.** pane 마다 얼마나 들고 있을 것인가. 스파이크 G 는 1MB 를 썼다. 셸 pane 기준이고,
에이전트 pane 에도 들 것인지는 별개다 — 흔들기로 화면은 오지만 사람이 위로 스크롤해 보고 싶어 할 수 있다.

**안 잰 것.** Classic 렌더러, codex·opencode, 끊긴 동안 출력이 있는 경우, 크기가 바뀐 채로 재접속.
서버에 헤드리스 에뮬레이터를 두는 길(VS Code 방식)은 여전히 기본값이 아니다 — 흔들기가 되는 이상
그 비용을 낼 이유가 없다.

### ⑩ 자동 배치 — 밀 자리가 없을 때
**탐색 방식은 정해졌다(2026-09-07): termcanvas 식 밀어내기다.** 새 창을 못 박고 겹친 만큼만
최단 거리로 밀며, 밀린 창이 또 겹치면 이어서 민다. 겹치기 설정은 없앴다.
다섯 앱을 비교한 표는 `own-runtime.md` 의 "캔버스" 에 남는다 — cate 는 네 방향 광선,
opencove 는 링 탐색 뒤 **만들기를 거부**, nodeterm 은 포기하고 겹치고, ccanvas 는 충돌 검사조차 안 한다.

**남은 것은 밀 자리가 없을 때다.** 겹치기를 없앴으니 이건 피할 수 없다. 세 갈래로 본다.
- (a) **캔버스 밖으로 민다.** 캔버스가 무한하다고 보고, 밀려난 창은 왼쪽 목록으로 찾아간다.
  카메라 줌을 뺐으므로 **화면 밖을 한눈에 볼 방법이 없다** — 목록과 확대 보기가 그 값을 낸다.
- (b) **가장자리에서 멈추고 새 창을 줄인다.** 캔버스를 뷰포트로 묶는다. 창이 계속 작아진다.
- (c) **밀리는 대신 새 창이 아래로 내려간다.** cate 가 자리 없을 때 하는 것과 같다.

같이 정할 것.
- **밀리는 것을 애니메이션으로 보여 줄지.** 창이 저절로 움직이는 건 처음 보면 놀라는 동작이다.
- **되돌리기가 필요한지.** 민 다음에 원래 자리로 돌릴 수 있어야 하는가.
- **기본 크기.** cate 는 640x400 고정, termcanvas 는 마지막으로 조절한 크기를 기억한다.
  우리는 창을 키우고 글자를 줄이기로 했으니(2026-09-07) 그 기준값도 여기서 정한다.
- **반복 한도.** termcanvas 는 20회에서 끊는다. 안 풀리면 무엇을 하는가.

## 이전 프로젝트에서 배운 것 (되풀이하지 마라)

- **혼자 재면 아무 뜻이 없다.** "40MB" 는 비교 대상이 있어야 크고 작음이 생긴다.
- **벤치마크는 그럴듯한 숫자로 거짓말한다.** `ps` 에 `-p` 를 빼먹어 머신 전체를 합산했고, tmux 를
  전용 소켓 없이 띄워 남의 세션까지 쟀고, 배수 루프에서 잠들어 자기 루프를 쟀다.
  **재는 코드부터 의심해라.**
- **느리지 않은 것을 고치지 마라.** 최적화 전에 어디가 느린지 측정한다.
- **전제가 바뀌면 결론도 다시 적어라.** 근거가 사라졌는데 결론만 남으면 "왜 만들었지?"에 답을 못 한다.
- **엔진을 먼저 받아들이고 요구를 나중에 물었다 — 두 번.** zellij(타일링이라 자유 배치 불가, 설치
  세 줄) 와 herdr(남의 런타임 종속). 요구 — 자유 배치, 설치 한 줄, 종속 없음, UI 보다 오래 사는
  세션 — 를 먼저 적고 엔진을 고른다.

## 이 프로젝트에서 배운 것

- **스키마에 있다고 구현된 게 아니고, 없다고 없는 것도 아니다.** 메서드는 호출해 보고 나서
  "있다"고 적는다. 모르는 필드는 오류 없이 버려진다.
- **소켓 API 만 보지 마라.** herdr 의 답은 `--help` 의 `terminal` 그룹에 있었다. CLI 도 API 다.
- **측정 스크립트가 pane 안에서 죽으면 숫자가 그럴듯하게 작아진다.** 부하를 만든 쪽의 마지막
  줄을 같이 찍어라.
- **대기 루프의 종료 조건에 현재 상태를 넣지 마라.** "이미 done" 을 종료 조건으로 잡아 2ms 에
  빠져나왔다. 기다리는 상태만 종료 조건에 둔다.
- **텍스트와 Enter 를 한 번에 쓰지 마라.** Claude Code 가 제출하지 않는다. 첫 훅 스파이크가
  이걸로 90초 대기를 두 번, 180초를 버렸다.
- **한 번 잰 숫자는 한 번 잰 숫자다.** 표본 수와 측정 창을 숫자 옆에 적어라.
  폴링으로 잰 시각은 그 주기보다 정밀하게 말하지 마라.
- **에이전트 상태를 믿고 자동으로 키를 보내면 사고가 난다.** codex 업데이트 대화상자가 `idle` 로
  보였고, 거기에 보낸 Enter 가 업데이트를 실행했다.
- **테스트 서버·에이전트는 깨끗한 환경에서 띄워라.** 자식이 환경변수를 물려받는다.
- **"아무도 안 만들었다" 는 검색 범위와 함께 적어라.** herdr 위 캔버스는 없었지만 Electron 캔버스는
  여섯 개가 넘었다. 빈자리는 좁게, 정확히 말한다.
- **전임 프로젝트의 기록을 인용할 때는 결론까지 읽어라.** polycanv 가 "글자를 못 줄인다" 로 막힌
  것으로 적었지만, 그 이슈(#20)는 "브라우저가 공짜로 준다" 로 닫혀 있었다.
