# 정한 것과, 일부러 안 정한 것

## 정한 것 (근거 있음 — 뒤집으려면 근거를 대라)

**런타임은 herdr 를 쓴다.** PTY·영속성·상태 감지를 직접 만드는 건 몇 달짜리이고,
herdr 가 러스트로 그걸 하고 있으며 유지되고 있다(별 3만+, Apache-2.0).
직전 프로젝트(polycanv)에서 그 절반을 파이썬으로 만들다가 이 결론에 왔다.

**프런트엔드는 브라우저 하나.** 줌이 공짜로 오고, OS 별 패키징이 없고, `--app=` 으로
창처럼 쓸 수 있다. 셋(앱·웹·CLI)을 만들면 기능마다 세 군데를 고쳐야 하고
그게 곧 "무겁다"는 평의 출처다.

**CLI 프런트엔드는 안 만든다.** herdr 에 TUI 가 있다.

**Electron 은 안 쓴다.** 무겁다는 게 이 프로젝트가 피하려는 바로 그것이다.
창이 필요하면 Tauri.

**`127.0.0.1` 밖으로 열지 않는다.** 이걸 HTTP 로 여는 건 셸을 여는 것이고 인증이 없다.
원격은 `ssh -L` 로 넘긴다. **host 를 바꾸는 옵션 자체를 두지 않는다** — 잊어서가 아니라 뺀 것이다.

## 안 정한 것 (첫 스파이크 뒤에 정한다)

### ① 웹 스택
프레임워크를 쓸 것인가. "가볍게"가 목표이므로 **기본값은 안 쓰는 것**이고,
쓰자고 하려면 이유를 대야 한다. xterm.js 는 어차피 필요하다.

### ② 다리(server)의 언어
- **TypeScript**: 프런트와 한 언어, xterm.js 와 같은 생태계, 배포가 한 덩어리
- **Python**: 익숙하고, polycanv 에서 쓰던 것을 가져올 수 있다

출력 스트리밍이 어떻게 되느냐(스파이크 ①)에 따라 다리가 하는 일의 양이 달라진다.
그걸 보고 정한다.

### ③ 자유 배치 좌표를 어디에 두는가
herdr `layout.export` / `layout.apply` 에 실을 수 있는지부터 확인한다.
**되면 herdr 가 재시작 후 배치까지 되살려 주므로 palmer 가 할 일이 없다.**
안 되면 palmer 가 따로 보관한다.

### ④ 창으로 낼 것인가
브라우저 탭 → `--app=` 창 → Tauri 순으로 무거워진다.
**웹으로 먼저 만들면 나중에 창으로 감싸는 건 작은 일이고, 반대는 아니다.**

### ⑤ 가벼움의 기준
"무겁다"에 반대해서 만드는 것이므로 **숫자로 말할 수 있어야 한다.**
무엇을 잴지(첫 화면까지의 시간, 유휴 CPU, 창 8개일 때 메모리, 번들 크기)와
넘으면 안 되는 선을 정한다. **비교 대상 없이 재면 의미가 없다** —
herdr TUI 단독, palmer 를 얹었을 때, 가능하면 Orca.

## 이전 프로젝트에서 배운 것 (되풀이하지 마라)

- **혼자 재면 아무 뜻이 없다.** "40MB" 는 비교 대상이 있어야 크고 작음이 생긴다.
- **벤치마크는 그럴듯한 숫자로 거짓말한다.** `ps` 에 `-p` 를 빼먹어 머신 전체를 합산한
  적이 있고, 숫자가 그럴듯해서 한참 못 알아챘다. **재는 코드부터 의심해라.**
- **느리지 않은 것을 고치지 마라.** 최적화 전에 어디가 느린지 측정한다.
- **전제가 바뀌면 결론도 다시 적어라.** 근거가 사라졌는데 결론만 남으면
  나중에 "왜 만들었지?"에 답을 못 한다.
