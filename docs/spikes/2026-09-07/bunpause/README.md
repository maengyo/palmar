# 스파이크 I — Bun 이 흐름 제어를 할 수 있는가 (2026-09-07 저녁, ② 의 마지막 항목)

스파이크 D 에 **"Bun 은 `Bun.Terminal` 에 pause 가 없어 못 멈춘다. 우회하려면 자식에게 SIGSTOP 을
보내야 하는데 그건 다른 종류의 값이다"** 라고 적고 재지 않았다. 재보니 **결론은 맞고 이유가 틀렸다.**

## 1. `sh -c` 에 SIGSTOP → 된다 (`pause.ts`)

| | 받은 것 | bun CPU | RSS | 자식 CPU |
|---|---|---|---|---|
| 최대 출력 | 5.8MB/s | 46% | 31MB | 100% |
| **SIGSTOP** | **0** | **0%** | 32MB | **0%** |
| SIGCONT | 5.8MB/s | 45% | 32MB | 98% |

메모리도 안 늘었다. **여기까지만 보면 Bun 도 흐름 제어가 된다.**

## 2. 그런데 실제 pane 은 `sh -i` 다 (`pause2.ts`, `fg.py`)

palmar 의 pane 은 셸이고, 출력을 내는 것은 사용자가 그 안에서 띄운 **자식**이다.
대화형 셸은 잡 제어를 하므로 **자식이 자기 프로세스 그룹을 갖는다.**

`fg.py` 로 파이썬에서 정확히 확인했다:

```
셸 pid=15816 pgid=15816  |  PTY 포그라운드 pgid=15817  → 다르다 (잡 제어)
  1. 그대로               9.6MB
  2. 셸 그룹에 STOP       9.6MB     ← 안 먹는다
  3. 포그라운드에 STOP    0.0MB     ← 먹는다
  4. CONT 로 재개         9.7MB
  5. 그냥 안 읽기 → 자식 CPU 0.3%   ← 커널 버퍼가 차면 write 에서 막힌다
```

**멈추려면 PTY 의 포그라운드 프로세스 그룹을 알아야 한다** — 터미널이 Ctrl+Z 로 하는 그것이고,
`tcgetpgrp(master_fd)` 로 얻는다.

## 3. Bun 은 그 fd 를 안 내준다 (`ffi.ts`)

`bun:ffi` 로 libc 를 여는 것은 **된다** — `tcgetpgrp`·`killpg` 를 부를 수 있다.
그런데 `Bun.Terminal` 이 내주는 것은 이것뿐이다:

```
close, closed, controlFlags, inputFlags, localFlags, outputFlags,
ref, unref, resize, setRawMode, write, constructor
```

**pause 도 없고 fd 도 없다.** fd 가 없으면 `tcgetpgrp` 를 부를 수 없고, 그러면 무엇을 멈춰야 할지
알 수 없다. 파이썬처럼 "안 읽기" 도 못 한다 — `data` 콜백이 밀어 넣는 구조라 안 읽을 방법이 없다.

## 결론

| | Python | Bun |
|---|---|---|
| 흐름 제어 방법 | **그냥 안 읽는다**(`remove_reader`) | 없다 |
| 왜 | 자식이 write 에서 막힌다. 신호도 프로세스 그룹도 필요 없다 | fd 도 pause 도 안 준다 |
| 잡 제어 영향 | 없다 | — |

**파이썬 쪽이 이기는 이유는 기능이 더 많아서가 아니라 fd 를 그냥 주기 때문이다.**
그리고 "안 읽기" 는 신호를 안 쓰므로 **의미도 더 낫다** — SIGSTOP 은 프로세스를 통째로 얼려서
API 응답을 기다리는 에이전트의 타이머까지 멈추지만, 안 읽기는 출력이 막힐 뿐이다.

**스파이크 D 의 RSS 87MB 를 이제 설명할 수 있다.** 그건 Bun 판이 게을러서가 아니라 **막을 방법이
없어서** 쌓인 것이다. 다만 그 실행의 `paused` 플래그는 아무것도 안 막고 있었으므로,
"막아 보고 실패한 값" 이 아니라 "막을 수단이 없다는 값" 으로 읽어야 한다.

## 안 잰 것

- Bun 이 `Bun.Terminal` 없이 PTY 를 여는 다른 길(FFI 로 `openpty` 직접 호출). 될 것으로 보이지만
  그러면 Bun 의 장점인 "내장 PTY" 를 안 쓰는 셈이라 재지 않았다.
- `ps` 로 포그라운드 그룹을 추정하는 우회로. 폴링이고 경합이 있어 후보로 안 봤다.
- Bun 이 나중에 fd 나 pause 를 열어 줄 가능성. 이슈 #41410 은 아직 열려 있다.
