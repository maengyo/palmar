# 스파이크 H — 설치 한 줄이 실제로 얼마인가 (2026-09-07 저녁, ② 의 마지막 입력)

② 에서 안 잰 것이 이것 하나였다. ⑦ 이 (b) 로 정해져 fd 전달이 기준에서 빠졌으니,
**남은 기준은 흐름 제어와 설치 둘**이다.

## 재는 법

이 기계에 이미 깔린 것을 지우지 않고, **깨끗한 맥이 갖는 것만으로** 스파이크 코드가 도는지 본다.
`/opt/anaconda3/bin/python3`(3.13) 가 아니라 `/usr/bin/python3` 로 돌린다.

## 결과 — 파이썬은 내려받을 것이 0 이다

`/usr/bin/python3` 는 **3.9.6** 이다. 그걸로:

| | 결과 |
|---|---|
| 네 스파이크 문법 | 전부 통과 |
| 서버 뜨기 · 정적 파일 | `200` |
| 웹소켓 업그레이드 | `101` |
| **PTY 실제 실행** | `echo HELLO-FROM-39` 가 돌아왔다 |
| **fd 전달(핸드오프)** | 구멍 0, 끊김 47.5ms |

**3.9 를 바닥으로 잡으면 파이썬 쪽 런타임 설치는 없다.**

## 그리고 이게 핵심이다 — git 이 있으면 python3 가 있다

macOS 의 `/usr/bin/python3` 는 Xcode CLT 로 넘기는 심이다. CLT 가 없으면 설치 대화상자가 뜬다.
그래서 "CLT 없는 맥" 이 파이썬 쪽의 유일한 약점인데, **확인해 보니 그 심이 `git` 과 같은 파일이다.**

```
/usr/bin/cc  /usr/bin/clang  /usr/bin/git  /usr/bin/make  /usr/bin/python3
    → 다섯 개가 전부 118,864 바이트, md5 해시 1개 (= 같은 바이너리)
```

**`git` 이 도는 기계는 `python3` 가 도는 기계다.** palmer 사용자는 코드 위에서 코딩 에이전트를
돌리는 사람이므로 git 이 없을 수가 없다. 그러니 "CLT 없는 맥" 은 palmer 사용자에게 사실상 없다.

## 안 잰 것

- **CLT 없는 맥.** 지울 수 없으니 못 쟀다. 위 논리는 해시가 같다는 사실 + "사용자는 git 을 쓴다"
  는 추론이다.
- **리눅스·WSL.** 이 기계에 없다. python3 는 사실상 모든 배포판에 있고 WSL 안도 같지만 확인은 안 했다.
- **윈도우 네이티브.** 우리는 WSL 로 푼다고 정했으므로(README) 범위 밖이다.
- **파이썬 3.9 로 계속 갈 때의 값.** 3.10+ 의 편의 문법을 못 쓴다. 스파이크 넷은 이미 3.9 에서
  도는데, 제품 코드가 커지면 다시 볼 일이다.
