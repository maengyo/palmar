# 스파이크 F — 재접속 복원: SIGWINCH 만으로 되는가 (2026-09-07 저녁, #18)

**왜 잰다.** 탭을 닫았다 열면 브라우저에는 빈 화면이 온다. 데몬도 PTY 도 살아 있는데,
새 클라이언트에게 무엇을 보낼 것인가. alt-screen 앱은 스크롤백을 재생해도 화면이 안 만들어진다 —
재생하면 그 세션의 모든 다시 그리기가 순서대로 흐를 뿐이다. 가장 싼 길은 크기를 한 칸 바꿨다
되돌려 **앱이 스스로 다시 그리게** 하는 것이다.

**이 결과가 ⑦ 을 바꾼다.** 이걸로 충분하면 핸드오프에서 링버퍼를 넘길 이유가 줄고, 그러면
fd 전달의 값이 떨어지고, 그러면 ②(파이썬 대 Bun)가 다시 열린다.

## 어떻게 쟀나

화면을 **둘 만들어 비교한다**(pyte). 바이트 수를 세는 게 아니라 실제로 그려 본다.

- `full` — 처음부터 모든 바이트를 먹인 화면 = 계속 보고 있었다면 봤을 것
- `fresh` — **재접속 시점 이후 바이트만** 먹인 화면 = 새로 붙은 브라우저가 받는 것

아무것도 재생하지 않고 `TIOCSWINSZ` 로 `(rows, cols-1)` → 0.25초 → `(rows, cols)` 만 한다.
`fresh == full` 이면 흔들기만으로 복원된다는 뜻이다.

```sh
python3 reconnect.py claude "List exactly three fruits, one per line. No other text."
python3 reconnect.py shell
```

## 결과 (Claude Code 2.1.263, 100x30, 각 1회)

| 무엇 | alt-screen | 흔든 뒤 받은 바이트 | 판정 |
|---|---|---|---|
| `zsh -f` | 아니오 | 50B | **부족하다** — 프롬프트 한 줄만 다시 그린다 |
| `claude` · 짧은 대화 | 예 | 4362B | **복원된다** |
| `claude` · 화면 넘치는 출력 | 예 | 3373B | **복원된다** |

**claude 는 흔들면 전체 화면을 다시 그린다.** 짧은 대화에서는 배너·질문·답(Apple/Banana/Cherry)·
소요 시간·대화상자·입력줄까지 20줄이 바이트 하나 재생하지 않고 그대로 돌아왔다.
화면을 넘치는 출력(1~40)에서도 보이는 부분(17~31)이 정확히 같았다 — 위로 밀려난 1~16 은
양쪽 다 없다. alt-screen 에는 스크롤백이 없으니 그게 맞는 동작이다.

**셸은 안 된다.** alt-screen 이 아니라서 흔들어도 프롬프트만 다시 그린다.
셸 pane 은 **원시 바이트 재생**이 답이고, 그래서 링버퍼가 필요하다 — 다만 alt-screen 앱보다
훨씬 싸다(셸은 화면을 다시 그리지 않으므로 재생이 곧 화면이다).

## 안 잰 것

- **Classic 렌더러.** 이번 실행은 alt-screen 으로 떴다. 조사에 따르면 2026-05-06 이후 처음 쓴
  사용자만 기본 fullscreen 이고 환경변수·저장된 설정이 뒤집는다. Classic 은 따로 봐야 한다.
- **codex · opencode.** claude 만 쟀다.
- **끊긴 동안 출력이 있는 경우.** 세 번 다 `끊긴 동안 0B` 였다 — 에이전트가 놀고 있을 때만 쟀다.
  일하는 중에 끊었다 붙으면 어떻게 되는지는 안 봤다.
- **여러 번.** 각 1회다. 흔든 뒤 3초를 기다렸는데 그게 얼마나 여유 있는 값인지 모른다.
- **크기가 바뀐 채로 재접속.** 브라우저 창 크기가 달라진 상태로 붙는 경우가 실제로 더 흔하다.
  그때는 흔들 필요도 없이 진짜 리사이즈가 일어나므로 더 쉬울 것으로 보이지만, 확인은 안 했다.

## 곁다리로 확인된 것

`pyte` 가 `claude` 의 private DSR(`ESC[?6n` 류)에서 `TypeError` 를 낸다. `Screen` 을 감싸
`report_device_status` 를 삼키게 했다. 서버에서 화면을 해석할 일이 생기면 다시 만날 문제다 —
그리고 그건 우리가 기본값으로 안 하기로 한 길이다(⑨).
